开一扇窗口

本节目标：开一扇能持续重绘的窗口，看到会「呼吸」的清屏色。跑起来应该弹出一个 640×480 的窗口，颜色缓慢地来回变；点右上角的 X，进程真的退出。

$ racket 01-window/window.rkt

计算位置窗口、GL 上下文、事件循环和 viewport 状态在 CPU（Racket/GUI）侧准备；gl-clear、swap-gl-buffers 是 CPU 下给 GPU 的命令。本课还没有顶点/片元着色器，GPU 只执行清屏和缓冲交换这两个固定动作；下一课才把顶点数据送进去。

1.1 OpenGL 不提供窗口

OpenGL 的职责只有一条：往「某块画布」上画东西。窗口、标题栏、鼠标键盘事件、定时器，这些都不归它管，规范里根本没有这类函数。所以任何 OpenGL 程序都得先借一个 GUI 库解决「画布从哪来」，再把 OpenGL 挂上去。

learnopengl 用 GLFW，我们用 Racket 自带的 racket/gui。三个类各管一件事：

  • frame%：窗口本身——标题栏、边框、关闭按钮。
  • canvas%：窗口里的一块可绘制区域，GL 上下文就建在它身上。
  • timer%：定时器，用来定期请求重绘。

1.2 GL 上下文

OpenGL 没有全局状态：颜色、缓冲、着色器程序全都住在一个叫「上下文」（context）的环境里。一块画布对应一个上下文，所有 gl-* 命令都发给「当前上下文」。

于是每个 gl-* 命令都得先回答一个问题：发给谁？Racket 这边的办法是用 with-gl-context 把绘制代码包起来——它先切到这块画布的上下文，再执行你给的 lambda，退出时切回去。不进去的话，gl-* 不知道命令该发给谁。

上下文是建画布的时候创建的，创建前先给它一份配置：

01-window/window.rkt源码 ↗
(define cfg (new gl-config%))
;; core profile：只用现代可编程管线，不要旧式固定管线（和 shader 里的 330 core 对应）
(send cfg set-legacy? #f)

gl-config% 来自 racket/draw。set-legacy? #f 就是上一课 0.6 讲的 core profile 那一端：只要现代可编程管线。

1.3 窗口与画布

frame% 拿来就能用，但默认的关闭行为只是把窗口藏起来——窗口不见了，进程还活着。要真正退出，得派生一个子类，在 on-close 里补上 (exit 0)：

01-window/window.rkt源码 ↗
;; frame% 是窗口类；这里派生一个子类，只为加一件事：点 X 时真正退出进程
;; （默认只是把窗口藏起来）。
(define gl-frame%
  (class frame%
    ;; on-close：点 X 时系统调的方法。
    ;; define/augment：在父类实现之外追加动作（不替换）。
    (define/augment (on-close)
      (inner (void) on-close)   ; 先走父类原本的关闭流程
      (exit 0))                 ; 再结束进程
    (super-new)))               ; 调用父类构造器

坑on-close 的父类实现只负责隐藏窗口，所以不写这个子类的话，点了 X 窗口消失、进程不退（终端里能看到 racket 还在）。注意用的是 define/augment：它在父类实现之外追加动作，不替换父类实现，所以要先 inner 走完父类的关闭流程，再 exit。

画布这边，canvas% 的 style 里加 'gl，它就会在自己身上创建一个 GL 上下文；再加 'no-autoclear，是让系统别自动擦背景——擦除交给我们自己的 gl-clear 管，清屏色才完全由程序说了算。

把三者装起来：

01-window/window.rkt源码 ↗
(define frame (new gl-frame% [label "01 窗口"] [width 640] [height 480]))
(define canvas (new gl-canvas%
                    [style '(gl no-autoclear)]
                    [gl-config cfg]
                    [parent frame]))
(send frame show #t)

canvas 创建出来时已经带着 cfg 和父窗口，show #t 之后窗口才出现在屏幕上、画布才有实际尺寸。

1.4 on-size 与 viewport

顶点坐标是标准坐标，范围 -1..1，跟窗口有多大、多少个像素没有关系。把它贴到画布上的哪块像素矩形，由 viewport 决定——设好之后，所有绘制都落在这一块矩形里。窗口尺寸变了就得重设：

01-window/window.rkt源码 ↗
    ;; on-size：窗口尺寸变化时回调。
    ;; 顶点坐标是标准坐标（-1..1），gl-viewport 决定它贴到窗口的哪块像素矩形；
    ;; 参数是 (左下角 x, 左下角 y, 宽, 高)，这里铺满整个画布。
    (define/override (on-size _w _h)
      (with-gl-context
       (lambda ()
         (define-values (cw ch) (get-gl-client-size))
         (gl-viewport 0 0 cw ch))))

gl-viewport 的四个参数是（左下角 x, 左下角 y, 宽, 高），原点在画布左下角；get-gl-client-size 给的是画布客户区的宽高。这里让视口铺满整块画布，所以窗口怎么变，画面都正好占满。

注意 viewport 也必须写在 with-gl-context 里面：它是一条 GL 命令，同样要知道发给哪个上下文。

1.5 on-paint 与双缓冲

系统在「需要重画」时回调 on-paint。所有绘制都写在这里——不是写在某个循环里，也不是写在定时器里（原因见 1.6）。

绘制前先用 with-gl-context 切上下文，然后按上一课 0.3 的顺序来：gl-clear-color 只设状态，gl-clear 才真的擦。最后一句 swap-gl-buffers 是双缓冲翻页：

01-window/window.rkt源码 ↗
    ;; on-paint：系统需要重画时回调。所有绘制都写这里。
    (define/override (on-paint)
      ;; with-gl-context：先切到本画布的上下文，再执行 lambda。
      ;; 不进去的话，gl-* 不知道命令该发给谁。
      (with-gl-context
       (lambda ()
         ;; 用经过的时间做一个会"呼吸"的颜色。
         ;; 用单调时钟，别数"画了多少帧"——定时器间隔只是约数，会漂移。
         (define t (/ (- (current-inexact-monotonic-milliseconds) start-ms) 1000.0))

         ;; gl-clear-color(r, g, b, a)：设清屏色，只"记住"，不画。
         ;; gl-clear(mask)：真正擦除；gl-color-buffer-bit 表示颜色缓冲
         ;; （它是位掩码常量，以后要同时擦深度缓冲时把掩码"按位或"起来）。
         (gl-clear-color (* 0.5 (+ 1.0 (sin t)))
                         (* 0.5 (+ 1.0 (sin (+ t 2.0))))
                         (* 0.5 (+ 1.0 (sin (+ t 4.0))))
                         1.0)
         (gl-clear gl-color-buffer-bit)

         ;; swap-gl-buffers：双缓冲翻页。我们画在"后台缓冲"，这一句整体翻到屏幕；
         ;; 直接画前台会看到画到一半的样子（闪烁）。
         (swap-gl-buffers))))

窗口系统给一块画布准备了两块同样大小的缓冲。你在后台缓冲上画，前台缓冲是屏幕正在显示的那一块；画完一次整体交换，屏幕立刻换成新画面。省掉这一句，画了半天也翻不到屏幕上（或者在慢的驱动上看到画面被撕成两半）。里面算颜色那几行 1.7 再讲。

1.6 事件驱动 vs learnopengl 的 while 主循环

这是 Racket 版和 C++ 版节奏上最大的差别，值得单独说清楚。

learnopengl 的程序有一个自己写的主循环：每一轮里自己处理输入、自己调 render、自己翻页、自己取事件。你写的代码占着这个循环不放，从头转到窗口关闭。C++ 版大致长这样：

learnopengl 的 C++ 主循环（对照，非本项目代码）
while (!glfwWindowShouldClose(window))
{
    processInput(window);     // 处理键盘鼠标
    render();                 // 画这一帧
    glfwSwapBuffers(window);  // 翻页
    glfwPollEvents();         // 取事件
}

racket/gui 是事件驱动的：你不写循环，程序把控制权交回给系统的 GUI 事件队列，它收到「该重绘了」「尺寸变了」「点了关闭」这类消息时，才回调你写的方法。同样是「一帧一帧地画」，结构从「一个大循环」变成「一组回调」。

维度 learnopengl 的 C++ 版 本教程的 Racket 版
谁在循环 自己写 while 循环，占着线程不放 不写循环，由 GUI 事件队列驱动
何时绘制 每一轮循环都调一次 render() 系统在需要重画时回调 on-paint
如何退出 窗口的关闭标志让 while 条件为假，循环结束 on-close 里 (exit 0) 结束进程
定时刷新 循环里 sleep，或靠 vsync 把这一轮堵住 timer% 定时请求重绘

关键点定时器只请求重绘，绘制永远在 on-paint 里。所以 timer% 的回调里只写 send canvas refresh 这一件事——绝不要把绘制代码搬进定时器回调，那样上下文不对、翻页时机也不对。

1.7 让它动起来

上面的窗口只在「系统觉得需要重画」时画一帧。要持续动下去，得有人不断告诉系统「该重画了」，timer% 就是干这个的：每 16ms 调一次回调，回调里只做一件事——请求重绘。

01-window/window.rkt源码 ↗
;; 上面只在"需要重画时"画一帧。timer% 每 16ms 调一次回调，
;; 回调里请求重绘，系统随后调 on-paint —— 定时器只请求，绘制永远在 on-paint。
(define timer
  (new timer% [interval 16]
              [notify-callback (lambda () (send canvas refresh))]))

16ms 只是按 60 次/秒估的间隔，不是硬保证：timer% 只负责「请求刷新」，系统可能合并或延迟；它也不是 vsync，画面仍可能撕裂。本教程先把「谁请求、谁绘制」讲清楚，帧率控制留到需要时再处理。

颜色怎么算出来的？把「从画布创建到现在过了多少毫秒」取出来，换算成秒：

01-window/window.rkt（on-paint 里）源码 ↗
         ;; 用经过的时间做一个会"呼吸"的颜色。
         ;; 用单调时钟，别数"画了多少帧"——定时器间隔只是约数，会漂移。
         (define t (/ (- (current-inexact-monotonic-milliseconds) start-ms) 1000.0))

这里用的是单调时钟，而不是「画了多少帧 × 16ms」。原因有两个：定时器的间隔只是约数，系统忙的时候 16ms 会变成 18、25ms，数帧的算法会越走越偏；而单调时钟只增不减，也不受系统时间被调整的影响，所以 t 和真实经过的时间一定对得上，动画速度不随机器负载变化。

三个 sin 的相位差分别是 0、2、4，红绿蓝三条通道错开变化，所以颜色不是简单地从黑到白再回来，而是在色环上绕。计时起点 start-ms 是画布创建时记下的，就在 class 体内，紧挨着 inherit 那几行。

把上面这条流程摊平来看就是图 1-1：标蓝的两格是我们要写的东西，其余是系统干的。

回到 1.5 提的双缓冲。一次 on-paint 里发生的事情，用图 1-2 表示就是：我们始终在后台缓冲上画，画完把两块缓冲整体交换。

两块缓冲交换之后，新的一帧在屏幕上，而后台缓冲里还留着上一帧的画面——所以下一轮 on-paint 开头必须再来一次 gl-clear，把它擦干净再画。

1.8 把窗口骨架收进 lib/window.rkt

01 的窗口代码只有这一课需要从零讲。后面每一课都要用同样的「建 frame / 建 canvas / 进入 GL 上下文 / 第一次 init / 每帧 draw / swap」骨架，如果每课都抄一遍，教程会被窗口代码淹没。所以从 02 开始统一 (require "../lib/window.rkt")，只写 init 和 draw。

lib/window.rkt 不是新的 OpenGL 机制，它就是把 01 的 gl-frame% / gl-canvas% 收成一个函数：

后面每课开头的固定写法
(require "../lib/window.rkt")

(define (init) ...)   ; 建 GPU 对象：program / VBO / VAO / 纹理 … 只跑一次
(define (draw) ...)   ; 每帧：清屏 + 绑定 + 画

(define-values (frame canvas)
  (make-window #:title "…"
               #:init init
               #:draw draw))
(send frame show #t)

make-window 的参数就是 01 里那些东西的封装：

参数对应 01 的哪一段什么时候调用
#:init第一次进入 GL 上下文后要做的初始化第一次 on-paint，只跑一次
#:draw每次 on-paint 里的绘制内容初始化成功后，每帧一次
#:on-sizeon-size 里重设 viewport 之后窗口尺寸变化时，参数是客户区宽高
#:on-keyon-char 收到的按键按下事件需要键盘的课才用
#:on-key-upon-char 收到的按键松开事件要判断“一直按住”时，和 #:on-key 配对使用（07.6）
#:on-focus画布获得/失去键盘焦点失焦时清空按键状态，避免粘键

「为什么 init 要单独拿出来」是关键：GPU 对象必须在已经进入 GL 上下文之后才能创建，而上下文要等画布第一次绘制时才存在。所以 make-window 在第一次 with-gl-context 里先跑 #:init，成功后才开始每帧跑 #:draw。这和 01 里 on-paint 的 inited? 标志是同一件事。

想对照实现，直接打开 lib/window.rkt：里面仍然是 01 的 gl-config%、with-gl-context、swap-gl-buffers、on-size、on-char，只是把重复部分固定下来。

完整代码

01-window/window.rkt，本节全部代码：

01-window/window.rkt源码 ↗
#lang glsl-opengl
;; ============================================================
;; 01 · 窗口 —— 先给 OpenGL 开一扇窗
;; 运行：racket 01-window/window.rkt
;; 上一课：00-intro.rkt
;; ============================================================
;; OpenGL 自己不提供窗口，它只往"某块画布"上画。所以先解决画布从哪来。
;; 这一课就三件事：拿到画布、画一帧（清屏）、让它动起来。

(require racket/class
         racket/gui       ; 窗口系统：frame% canvas% timer% 等
         racket/draw)     ; gl-config% 在这里

;; ---- 窗口 --------------------------------------------------
;; racket/gui 是事件驱动的：没有 while 主循环。你造好窗口、显示，
;; 系统在"该重画""点了关闭"时回调你写的方法。
;; frame% 是窗口类；这里派生一个子类，只为加一件事：点 X 时真正退出进程
;; （默认只是把窗口藏起来）。
(define gl-frame%
  (class frame%
    ;; on-close：点 X 时系统调的方法。
    ;; define/augment：在父类实现之外追加动作（不替换）。
    (define/augment (on-close)
      (inner (void) on-close)   ; 先走父类原本的关闭流程
      (exit 0))                 ; 再结束进程
    (super-new)))               ; 调用父类构造器

;; ---- GL 上下文 ---------------------------------------------
;; OpenGL 没有全局状态：颜色、缓冲、着色器程序都住在一个叫"上下文"的环境里。
;; 一块画布 = 一个上下文；所有 gl-* 命令都发给"当前上下文"。
(define cfg (new gl-config%))
;; core profile：只用现代可编程管线，不要旧式固定管线（和 shader 里的 330 core 对应）
(send cfg set-legacy? #f)

;; ---- GL 画布 -----------------------------------------------
;; canvas% 加上 'gl 样式，就会在自己身上创建 GL 上下文。
;;   'no-autoclear：别让系统自动擦背景，擦除我们自己用 gl-clear 控制。
(define gl-canvas%
  (class canvas%
    ;; inherit：把父类的方法拿进来，子类里才能直接调用
    (inherit with-gl-context swap-gl-buffers get-gl-client-size)

    (define start-ms (current-inexact-monotonic-milliseconds))  ; 动画计时起点

    ;; on-size：窗口尺寸变化时回调。
    ;; 顶点坐标是标准坐标（-1..1），gl-viewport 决定它贴到窗口的哪块像素矩形；
    ;; 参数是 (左下角 x, 左下角 y, 宽, 高)，这里铺满整个画布。
    (define/override (on-size _w _h)
      (with-gl-context
       (lambda ()
         (define-values (cw ch) (get-gl-client-size))
         (gl-viewport 0 0 cw ch))))

    ;; on-paint：系统需要重画时回调。所有绘制都写这里。
    (define/override (on-paint)
      ;; with-gl-context：先切到本画布的上下文，再执行 lambda。
      ;; 不进去的话，gl-* 不知道命令该发给谁。
      (with-gl-context
       (lambda ()
         ;; 用经过的时间做一个会"呼吸"的颜色。
         ;; 用单调时钟，别数"画了多少帧"——定时器间隔只是约数，会漂移。
         (define t (/ (- (current-inexact-monotonic-milliseconds) start-ms) 1000.0))

         ;; gl-clear-color(r, g, b, a)：设清屏色，只"记住"，不画。
         ;; gl-clear(mask)：真正擦除；gl-color-buffer-bit 表示颜色缓冲
         ;; （它是位掩码常量，以后要同时擦深度缓冲时把掩码"按位或"起来）。
         (gl-clear-color (* 0.5 (+ 1.0 (sin t)))
                         (* 0.5 (+ 1.0 (sin (+ t 2.0))))
                         (* 0.5 (+ 1.0 (sin (+ t 4.0))))
                         1.0)
         (gl-clear gl-color-buffer-bit)

         ;; swap-gl-buffers：双缓冲翻页。我们画在"后台缓冲"，这一句整体翻到屏幕；
         ;; 直接画前台会看到画到一半的样子（闪烁）。
         (swap-gl-buffers))))

    (super-new)))

;; ---- 组装 --------------------------------------------------
(define frame (new gl-frame% [label "01 窗口"] [width 640] [height 480]))
(define canvas (new gl-canvas%
                    [style '(gl no-autoclear)]
                    [gl-config cfg]
                    [parent frame]))
(send frame show #t)

;; ---- 让它动起来 --------------------------------------------
;; 上面只在"需要重画时"画一帧。timer% 每 16ms 调一次回调，
;; 回调里请求重绘，系统随后调 on-paint —— 定时器只请求，绘制永远在 on-paint。
(define timer
  (new timer% [interval 16]
              [notify-callback (lambda () (send canvas refresh))]))

试试看

  1. 把 timer% 的 interval 从 16 改成 500 → 重绘频率降到每半秒一次，颜色变化变成一格一格地跳，看起来又慢又卡。这也说明 t 是按真实时间算的：颜色该到哪儿到哪儿，只是画面更新得少了。
  2. 改三个 sin 的相位差，比如把 (+ t 2.0) 和 (+ t 4.0) 换成 t、(+ t 1.0) → 三条通道几乎同步变化，颜色从黑扫到白再回来，不再绕色环。
  3. 删掉 (swap-gl-buffers) 这一行 → 我们一直在后台缓冲上画，屏幕看的前台缓冲没被换过，画面要么停在最开始那一帧不动，要么在某些驱动上被撕成上下两半。
  4. 删掉 on-size 里的 (gl-viewport 0 0 cw ch)，然后拖拽窗口边框改尺寸 → 视口还是最初那块像素矩形，画面被拉伸（窗口变宽时横向扯长，变高时纵向扯长），而且它只占窗口左上角的一部分。

小结

概念 一句话
frame% 窗口本身；派生一个子类只为在 on-close 里 (exit 0)，让进程真的退出
canvas% 窗口里的画布；style 里加 'gl 才有 GL 上下文，加 'no-autoclear 把擦除交给自己
timer% 定时请求重绘，不参与绘制；每 16ms 一轮靠它驱动
GL 上下文 一块画布一个上下文，所有 gl-* 命令发给「当前上下文」
with-gl-context 把绘制代码包起来，先切到本画布的上下文再执行
