模型加载

本节目标：不再手写顶点数据，而是从 OBJ 文件读一个真实模型。我们加载经典的 Utah Teapot（1202 个顶点 / 2256 个三角形，带法线、没有 UV），用纯材质色 + 09 课的 Phong 光照画出来。跑起来应该看到一个旋转的茶壶，能看出壶身、壶嘴、把手和盖子的明暗。

$ racket 14-model-loading/model-loading.rkt

计算位置OBJ 解析、顶点/索引组装在 CPU；顶点变换、法线变换、光照在 GPU。模型加载本身不是 GPU 计算，它是在准备 GPU 要用的数据。

14.1 OBJ 文件长什么样

Wavefront OBJ 是纯文本格式，最常用的四类记录是：

  • v x y z：顶点位置，索引从 1 开始
  • vt u v：纹理坐标
  • vn x y z：法线
  • f v/vt/vn ...：面，用“位置/UV/法线”的索引引用前面三张表

本课用的模型是 assets/models/teapot.obj（Utah Teapot，经典测试模型；文件头保留了来源和 MIT 许可说明）。开头是：

# Utah Teapot (classic test model, original by Martin Newell)
# Source file: https://github.com/McNopper/OpenGL/blob/master/Binaries/teapot.obj
# Repository license: MIT
v 0.605903 0.005903 0.000000
v 0.000000 0.000000 0.000000
v 0.584584 0.005902 -0.162696
v 0.524218 0.005902 -0.307888
v 0.430191 0.005901 -0.430191
v 0.307888 0.005901 -0.524218
...
f 1//1 2//2 3//3
f 3//3 2//2 4//4
...

一个面可以是三角形，也可以是多边形。OBJ 还允许一个顶点在不同面上有不同的 UV/法线，所以“同一个位置”可能出现多次——这正是硬边和 UV 接缝的来源。

14.2 CPU 侧：解析 OBJ

lib/obj.rkt 是一个极简读取器，只做模型加载课需要的事：

  1. 按行读 v / vt / vn / f，忽略注释和材质指令。
  2. 把 1-based、负数索引统一成 0-based。
  3. 用 (v-index, vt-index, vn-index) 作为去重键，生成唯一的 obj-vertex。
  4. 多边形用扇形三角化：(0,1,2) (0,2,3) ...。
  5. 返回 obj-mesh：顶点表 + 三角形索引表。
(define mesh (read-obj "assets/models/teapot.obj"))

(obj-mesh-vertex-count mesh)   ; => 1202
(obj-mesh-index-count mesh)    ; => 6768（2256 个三角形 × 3）

这个茶壶文件只有 v 和 vn，没有 vt。loader 对缺失的 UV 给默认值；本课也就不用纹理，直接用材质色 + 法线光照。想验证 UV 加载，可以换一个带 vt 的模型。

注意：loader 不负责“计算缺失法线”或“合并相同顶点”。它只忠实解析文件；优化与容错是拓展方向。

14.3 从 obj-vertex 到 GPU 顶点

渲染用的顶点布局是：

(glsl-struct model-vertex (vec-3 pos) (vec-3 normal))

把 obj-vertex 逐个转成 model-vertex，铺平成一条 f32vector，再上传 VBO；索引表上传 EBO：

(define model-data
  (apply concat-vecs
         (for/list ([v (in-vector (obj-mesh-vertices mesh))])
           (model-vertex->f32vector
            (model-vertex (obj-vertex-pos v)
                          (obj-vertex-normal v))))))

(define model-indices
  (apply u16-array (vector->list (obj-mesh-indices mesh))))

属性布局仍然交给 glsl-vertex-layout!：shader 的 in 名和 model-vertex 字段名都是 pos / normal，编译期自动对齐 slot、stride、offset。

绘制时用 09 课已经熟悉的矩阵链路：

(define model-m
  (mat4-mul (m-scale (vec-3 0.8 0.8 0.8))
            (m-rotate-y t)))

(set-model-u-model! model-m)
(set-model-u-view! view)
(set-model-u-proj! proj)
(set-model-u-normal-matrix! (m-normal-matrix model-m))

14.4 本课的着色器

顶点着色器就是 09 课的标准三件套：位置 → 世界 → 观察 → 裁剪，同时把法线、世界位置、UV 传给片元。片元做一次简单的 Phong：

(float ambient 0.15)
(float diff (max (dot norm light-dir) 0.0))
(float spec (* (pow (max (dot view-dir reflect-dir) 0.0) 32.0) 0.4))
(vec-3 lit (* (+ ambient diff spec) u-light-color))
(set! frag-color (vec-4 (* lit u-object-color) 1.0))

茶壶没有 UV，所以本课不采样纹理；材质色用 u-object-color 给。法线仍然参与 diffuse/specular，壶身、壶嘴、把手和盖子的朝向不同，明暗就不同。

完整代码

14-model-loading/model-loading.rkt，本课全部代码（直接 racket 跑）：

14-model-loading/model-loading.rkt源码 ↗
#lang glsl-opengl
;; ============================================================
;; 14 · 模型加载：从 OBJ 文件到 GPU
;; 运行：racket 14-model-loading/model-loading.rkt
;; 上一课：13-text-3d/text-3d.rkt
;; ============================================================
;; 目标：不再手写顶点数据，而是从 assets/models/teapot.obj 读一个模型。
;;
;; 这是经典的 Utah Teapot：1202 个顶点 / 2256 个三角形，带法线，
;; 但没有 UV。用它正好说明：模型加载不只是“读位置”，还要处理法线，
;; 而 UV / 材质是另一层数据，缺了也能先用纯材质色 + 光照渲染。
;;
;; OBJ 文件里常见三张表：
;;   v  顶点位置
;;   vt UV
;;   vn 法线
;; 面用 f 引用它们：f v/vt/vn ...
;;
;; CPU 侧要做的事：
;;   1. 解析 OBJ（lib/obj.rkt）
;;   2. 把 obj-vertex 转成渲染用的交错顶点（model-vertex）
;;   3. 上传 VBO + EBO
;;   4. 用 model / view / proj / normal-matrix 画出来
;;
;; 想加载别的 OBJ：把路径换成自己的文件即可；复杂模型还需要材质、
;; 多 group、索引去重优化等，见页面最后的“拓展方向”。

(require racket/class
         racket/gui                     ; timer%
         racket/math                    ; degrees->radians
         "../lib/window.rkt"
         "../lib/gpu.rkt"
         "../lib/matrix.rkt"
         "../lib/obj.rkt")

;; ------------------------------------------------------------
;; 一、读 OBJ
;; ------------------------------------------------------------
(define mesh (read-obj (build-path (current-directory)
                                   "assets/models/teapot.obj")))

;; 渲染用顶点布局：位置 + 法线。
;; 字段名必须和 shader 的 in 名一致，glsl-vertex-layout! 才能自动对齐。
;; （loader 仍然支持 UV；这个 teapot 文件没有 vt，所以这里不需要。）
(shader-struct model-vertex (vec-3 pos) (vec-3 normal))

(define model-data
  (apply concat-vecs
         (for/list ([v (in-vector (obj-mesh-vertices mesh))])
           (model-vertex->f32vector
            (model-vertex (obj-vertex-pos v)
                          (obj-vertex-normal v))))))

(define model-indices
  (apply u16-array (vector->list (obj-mesh-indices mesh))))

(define model-index-count (obj-mesh-index-count mesh))

;; ------------------------------------------------------------
;; 二、着色器：纯材质色 + 简单 Phong
;; ------------------------------------------------------------
(glsl-shader model-vert
  (version 330 core)
  (layout (location 0) in vec-3 pos)
  (layout (location 1) in vec-3 normal)
  (uniform mat-4 u-model)
  (uniform mat-4 u-view)
  (uniform mat-4 u-proj)
  (uniform mat-3 u-normal-matrix)
  (out vec-3 v-normal)
  (out vec-3 v-frag-pos)
  (define (main) void
    (set! v-normal (* u-normal-matrix normal))
    (set! v-frag-pos (vec-3 (* u-model (vec-4 pos 1.0))))
    (set! gl-position (* u-proj (* u-view (* u-model (vec-4 pos 1.0)))))))

(glsl-shader model-frag
  (version 330 core)
  (in vec-3 v-normal)
  (in vec-3 v-frag-pos)
  (uniform vec-3 u-object-color)
  (uniform vec-3 u-light-pos)
  (uniform vec-3 u-light-color)
  (uniform vec-3 u-view-pos)
  (out vec-4 frag-color)
  (define (main) void
    (vec-3 norm (normalize v-normal))
    (vec-3 light-dir (normalize (- u-light-pos v-frag-pos)))
    (vec-3 view-dir (normalize (- u-view-pos v-frag-pos)))
    (vec-3 reflect-dir (reflect (- light-dir) norm))

    (float ambient 0.15)
    (float diff (max (dot norm light-dir) 0.0))
    (float spec (* (pow (max (dot view-dir reflect-dir) 0.0) 32.0) 0.4))
    (vec-3 lit (* (+ ambient diff spec) u-light-color))
    (set! frag-color (vec-4 (* lit u-object-color) 1.0))))

;; ------------------------------------------------------------
;; 三、GL 对象
;; ------------------------------------------------------------
(define model-program #f)
(define vao #f)

(glsl-uniform-setter! model-program model-vert model-frag #:prefix "model-")

(define (init)
  (set! model-program (own! 'program (build-program (gl-vertex-shader model-vert)
                                                    (gl-fragment-shader model-frag))))

  (gl-enable gl-depth-test)

  ;; ---- 模型 VAO / VBO / EBO ----
  (set! vao (own! 'vertex-array (vertex-array-new)))
  (gl-bind-vertex-array vao)

  (define vbo (own! 'buffer (buffer-new)))
  (gl-bind-buffer gl-array-buffer vbo)
  (buffer-upload gl-array-buffer model-data gl-static-draw)
  ;; shader 的 in 名 = model-vertex 字段名：pos / normal / uv
  (glsl-vertex-layout! model-vert model-vertex)

  (define ebo (own! 'buffer (buffer-new)))
  (gl-bind-buffer gl-element-array-buffer ebo)
  (buffer-upload gl-element-array-buffer model-indices gl-static-draw)

  (gl-bind-vertex-array 0))

;; ------------------------------------------------------------
;; 五、窗口 / 绘制
;; ------------------------------------------------------------
(define win-w 800)
(define win-h 600)
(define aspect (/ win-w win-h))

(define (draw)
  (gl-clear-color 0.08 0.10 0.16 1.0)
  (gl-clear (bitwise-ior gl-color-buffer-bit gl-depth-buffer-bit))

  (define t (/ (current-inexact-monotonic-milliseconds) 1000.0))
  (define eye (vec-3 4.5 3.0 6.5))
  (define view (m-look-at eye (vec-3 0.0 1.2 0.0) (vec-3 0.0 1.0 0.0)))
  (define proj (m-perspective (degrees->radians 45.0) aspect 0.1 100.0))

  ;; 模型自己绕 y 轴转，方便看背面和侧面
  (define model-m
    (mat4-mul (m-scale (vec-3 0.8 0.8 0.8))
              (m-rotate-y t)))

  (program-use model-program)
  (gl-bind-vertex-array vao)

  (set-model-u-model! model-m)
  (set-model-u-view! view)
  (set-model-u-proj! proj)
  (set-model-u-normal-matrix! (m-normal-matrix model-m))
  (set-model-u-object-color! (vec-3 0.82 0.55 0.35))
  (set-model-u-light-pos! (vec-3 4.0 5.0 4.0))
  (set-model-u-light-color! (vec-3 1.0 1.0 1.0))
  (set-model-u-view-pos! eye)

  (gl-draw-elements gl-triangles model-index-count gl-unsigned-short 0)
  (gl-bind-vertex-array 0))

(define-values (frame canvas)
  (make-window #:title "14 模型加载"
               #:width win-w
               #:height win-h
               #:init init
               #:draw draw
               #:on-size (lambda (cw ch) (set! aspect (/ cw ch)))
               #:on-close release-all!))
(send frame show #t)

;; 模型在转，需要定时器不断请求重绘
(define timer
  (new timer% [interval 16]
              [notify-callback (lambda () (send canvas refresh))]))

GPU 资源本节代码里每个 *-new / build-program 都用 own! 登记，关窗时 release-all! 统一删除。为什么这些句柄 GC 管不了，见 02 · 2.9。

14.5 试试看

  1. 非等比缩放：把 m-scale 改成 (vec-3 1.6 0.7 1.0)，观察明暗和高光是否被拉歪；再把 set-model-u-normal-matrix! 的参数换成“只取 model 左上 3×3、不做逆转置”的 naive 版本（09 课「试试看」第 ④ 条有完整写法），对比法线错误时画面怎么变。
  2. 换材质色和灯位：改 u-object-color、u-light-pos、eye，确认颜色乘法、点光方向和相机位置各自影响什么。
  3. 画两个茶壶：在 draw 里把 set-model-u-model! + set-model-u-normal-matrix! + gl-draw-elements 这段再写一遍，第二次用 (mat4-mul (m-translate (vec-3 2.5 0 0)) model-m)。每个物体都要重新传 model 和 normal matrix，但 VBO/EBO 可以共用。
  4. 换图元：把 gl-draw-elements gl-triangles 换成 gl-lines 或 gl-points。索引表不变，看到的是三角形边/顶点而不是实心面，正好检查网格拓扑。
  5. 没有法线的模型：复制一份 teapot.obj，删掉所有 vn 行（或找一个不带法线的 OBJ）再加载。loader 会给默认零法线，光照会大面积变黑；这能说明为什么本课要把法线一起上传。

14.6 拓展方向

  1. 材质 / 多 group：OBJ 的 usemtl / mtllib 指向 MTL 文件（漫反射、镜面、透明度等）。要做完整模型，需要按 group 拆分 draw call，并为每个材质绑定不同纹理/参数。
  2. 更大 / 更复杂的模型：当前 loader 只处理 v/vt/vn/f。真实模型还常有四边面、N 边形、多文件引用、纹理路径、变换层级等，需要更完整的解析器。
  3. 法线计算：如果 OBJ 没有 vn，可以按面法线或平滑法线（顶点邻接平均）计算。当前 loader 缺省给 (0,0,0)。
  4. 索引优化：当前去重键包含 vt/vn，UV 接缝会拆点。进一步可以按 GPU 缓存局部性重排索引（meshoptimizer 之类），提升顶点缓存命中率。
  5. 二进制 / glTF：OBJ 是教学友好的文本格式；生产环境更常用 glTF（二进制、内嵌材质/动画/骨骼）。下一步可以看 glTF 2.0 的 accessor / bufferView / 材质模型。
  6. 法线贴图 / 切线空间：模型加载常和 normal map 一起出现。需要为每个顶点准备 tangent / bitangent，或者在 shader 里用屏幕导数构造 TBN。
  7. 骨骼动画：OBJ 不支持骨骼；要做角色动画需要 glTF/FBX 的 skin / joint / weight 数据。
  8. 场景图：一个模型文件可能包含多个 node，每个 node 有自己的 transform。当前只画一个 mesh；真实场景需要递归遍历 node 树。
  9. 资源缓存：同一个模型被多个物体使用时，应该共享 VBO/EBO/纹理，而不是每个实例都上传一遍。

结论模型加载可以拆成三层：文件解析（OBJ → 顶点/索引）、GPU 上传（VBO/EBO/纹理）、场景变换（model/view/proj/normal matrix）。本课把三层都走了一遍；后续扩展通常发生在第一层（格式/材质/动画）和第三层（场景图/实例化）。

想看清 draw 背后发生了什么复习 04 · 用 CPU 走一遍渲染管线 用 Racket 把同一只茶壶画了一遍：顶点变换、光栅化、深度测试、透视校正、片元着色，每一步都写出来，并给出各自的执行次数和耗时。
