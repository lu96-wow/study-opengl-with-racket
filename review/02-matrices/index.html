复习 02 · 矩阵与计算位置

目标：把 05–07 的矩阵链路在 CPU 上亲手算一遍，再对照 GPU 顶点着色器里的同一行公式。你会看到：数学完全一样，区别只是「在哪里算、数据怎么流」。

$ racket review/02-matrices/matrix-review.rkt

R2.1 公式

GPU 顶点着色器每个顶点执行：

clip = u_proj · u_view · u_model · vec4(pos, 1.0)

ndc = clip.xyz / clip.w

CPU 版没有魔法，就是同样的矩阵乘法：

review/02-matrices/matrix-review.rkt（摘录）源码 ↗
(define model (m-translate (vec-3 0.5 0.0 -1.0)))
(define view  (m-look-at (vec-3 0.0 0.0 5.0) (vec-3 0.0 0.0 0.0) (vec-3 0.0 1.0 0.0)))
(define proj  (m-perspective (degrees->radians 45.0) (/ 4.0 3.0) 0.1 100.0))

(define mvp  (mat4-mul proj (mat4-mul view model)))
(define clip (mat4-mul-vec mvp (vec-4 0.5 0.0 0.0 1.0)))
(define ndc  (vec-3 (/ (vx clip) (vw clip))
                    (/ (vy clip) (vw clip))
                    (/ (vz clip) (vw clip))))

R2.2 CPU 还是 GPU

CPU 算GPU 算（本教程）
传什么传算好的顶点（世界/NDC）传原始顶点 + model/view/proj
每帧成本CPU 遍历所有顶点 + 重新上传 VBOCPU 只更新几个矩阵 uniform
适合顶点少、变化少、需要 CPU 读结果顶点多、相机/物体每帧变
优势简单、可调试、无需 GPU 回读并行、无中间结果上传

所以「把计算放到 GPU」不是唯一选择。它是一个数据流决策：计算本身（矩阵乘法）不变，变的是计算发生的位置和中间结果的传输成本。

记法model 把局部坐标搬到世界，view 把世界搬到相机，proj 把相机视锥压成裁剪空间。矩阵从右往左作用在顶点上：proj · view · model · p。
