复习 01 · API 与数据流

目标：把 02–04 用过的 OpenGL API 重新排一遍，分清哪些是「传数据」、哪些是「设状态」、哪些是「启动计算」。这一节不引入新效果，只做记忆整理。

$ racket review/01-api-flow/api-review.rkt

R1.1 API 不做计算

矩阵乘法、光照、纹理采样，都是 shader 或 CPU 代码里的公式。API 主要做三件事：

  • 传数据：gl-buffer-data、gl-tex-image-2d、gl-uniform-*
  • 设状态：gl-use-program、gl-bind-vertex-array、gl-enable
  • 启动计算：gl-draw-arrays / gl-draw-elements

api-review.rkt 会把这张表打印出来。核心对照：

API它改变什么数据方向
gl-create-shader / gl-shader-source / gl-compile-shader创建并编译 shaderCPU → GPU
gl-create-program / gl-attach-shader / gl-link-program链接 programGPU 内部
gl-gen-buffers / gl-buffer-data创建 VBO/EBO 并上传字节CPU → GPU
gl-gen-vertex-arrays / gl-vertex-attrib-pointer记录顶点格式CPU → GPU 状态
gl-tex-image-2d上传纹理像素CPU → GPU
gl-draw-elements跑顶点/片元 shaderGPU → 屏幕
raw 三角形：API 的顺序（摘录）
;; 编译 + 链接
(define vs (gl-create-shader gl-vertex-shader))
(gl-shader-source vs 1 (vector (glsl-program-src vert-src)) (s32vector ...))
(gl-compile-shader vs)
(define prog (gl-create-program))
(gl-attach-shader prog vs)
(gl-link-program prog)

;; 上传数据 + 记录格式
(gl-bind-buffer gl-array-buffer vbo)
(gl-buffer-data gl-array-buffer size data gl-static-draw)
(gl-bind-vertex-array vao)
(gl-vertex-attrib-pointer 0 3 gl-float #f 0 0)
(gl-enable-vertex-attrib-array 0)

;; 启动计算
(gl-use-program prog)
(gl-bind-vertex-array vao)
(gl-draw-arrays gl-triangles 0 3)

R1.2 你应该能回答

  1. 为什么 gl-vertex-attrib-pointer 没有 buffer 参数？它读的是当前绑定的哪个 buffer？
  2. 为什么 ELEMENT_ARRAY_BUFFER 的绑定属于 VAO，而 ARRAY_BUFFER 不属于？
  3. gl-draw-arrays 这一句到底启动了什么？CPU 在这之后还参与逐顶点/逐像素计算吗？
  4. 如果不用 GPU，CPU 要怎样算出同样的三角形？需要上传什么？

下一步复习 02 会把「矩阵计算」拆成 CPU 版和 GPU 版；复习 03 会把「光照计算」拆成逐顶点、逐片元和离线烘焙。
