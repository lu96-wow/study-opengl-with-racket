复习 03 · 光照：CPU 还是 GPU

目标：把 08–11 的 Phong 公式在 CPU 上算一遍，再对照片元着色器里的同一套公式。重点是看清「逐顶点 / 逐片元 / 离线烘焙」三种计算位置，而不是死记 API。

$ racket review/03-lighting/lighting-review.rkt

R3.1 公式

ambient = 0.15

diffuse = max(dot(n, l), 0)

specular = pow(max(dot(v, r), 0), 32) · 0.4

color = (ambient + diffuse + specular) · lightColor · objectColor

review/03-lighting/lighting-review.rkt（摘录）源码 ↗
(define n (vnormalize normal))
(define l (vnormalize (vsub light-pos frag-pos)))
(define v (vnormalize (vsub view-pos frag-pos)))
(define r (vreflect (vneg l) n))

(define ambient 0.15)
(define diff (max (vdot n l) 0.0))
(define spec (* (expt (max (vdot v r) 0.0) 32.0) 0.4))
(define color (vmul (vmul light-color (+ ambient diff spec)) object-color))

R3.2 计算放在哪

做法在哪算特点
Gouraud（逐顶点）CPU 或顶点着色器每顶点算一次，三角形内部插值颜色；高光容易糊
Phong（逐片元）片元着色器每像素算一次；高光清晰，成本随像素数增长
lightmap / 顶点色CPU 离线烘焙运行时只采样；适合静态光照，不适合动态灯

GPU 不是唯一选择，但它是「动态、逐像素、数据量大」时最自然的选择。CPU 逐顶点或预烘焙在静态场景里更便宜，也更容易调试。

一句话API 只负责把 uniform、normal、frag-pos 送进 shader 并启动绘制；到底逐顶点还是逐片元算，是你选择的计算位置。
