第一个三角形

本节目标：把三个顶点变成屏幕上的三角形，然后换成用索引画矩形。跑起来应该看到 triangle.rkt 一个橙色三角形，rectangle.rkt 一个蓝色矩形。

$ racket 02-hello-triangle/triangle.rkt
$ racket 02-hello-triangle/rectangle.rkt

计算位置CPU 准备顶点数据；GPU 顶点着色器算 gl-position，片元着色器算颜色；OpenGL API 只负责上传数据、设状态、启动绘制。CPU 也可以先算好变换再上传，但顶点多/相机每帧变时通常不划算（见 R2）。

2.0 先看 raw OpenGL，再用便利层

从本课开始，代码里会出现 build-program、buffer-new、buffer-upload、vertex-array-new、program-use 这些名字。它们不是 GLSL 语法，也不是 OpenGL API，而是 racket-shader-opengl 的便利层：把一串 raw gl-* 调用收成一个函数。

另外，(glsl …) 是语言层，不是 OpenGL 便利层——它只负责把 S 表达式生成 GLSL 文本；vec-array / u16-array 则属于值层便利，负责把 CPU 数据整理成 ffi 向量。这几层要分开看。

先看一眼 shutdown本课代码末尾有一个 shutdown，里面是几行 program-delete / vertex-array-delete / buffer-delete，关窗时由 #:on-close 触发。为什么 GPU 对象必须手动删、为什么句柄要提到顶层，见 2.9。

如果一上来就只看到便利层，很容易把「便利层的行为」误当成「OpenGL 的规则」。所以本课先把 raw 流程走一遍。建议先打开 compare/raw-triangle.rkt：它不用 racket-shader，直接拿 opengl 包画同一个三角形，正好可以对照。

一个三角形在 raw OpenGL 里要经过这些步骤：

  1. 编译 shader：gl-create-shader → gl-shader-source → gl-compile-shader → 用 gl-get-shader-iv 查 gl-compile-status；失败就取 info log。
  2. 链接 program：gl-create-program → gl-attach-shader ×2 → gl-link-program → 查 gl-link-status。
  3. 上传顶点：gl-gen-buffers 拿 id → gl-bind-buffer gl-array-buffer → gl-buffer-data 把字节和长度交给 GL。
  4. 建 VAO：gl-gen-vertex-arrays → gl-bind-vertex-array → gl-vertex-attrib-pointer 描述格式 → gl-enable-vertex-attrib-array 打开槽。
  5. 绘制：gl-use-program → gl-bind-vertex-array → gl-draw-arrays。
raw 骨架（省略状态检查和错误处理）
;; 需要 (require ffi/vector)：s32vector / u32vector-ref

;; 1. 编译 shader：源文本来自 racket-shader 的 glsl-program-src
(define vs (gl-create-shader gl-vertex-shader))
(gl-shader-source vs 1 (vector (glsl-program-src vert-src))
                  (s32vector (string-length (glsl-program-src vert-src))))
(gl-compile-shader vs)
(define fs (gl-create-shader gl-fragment-shader))
(gl-shader-source fs 1 (vector (glsl-program-src frag-src))
                  (s32vector (string-length (glsl-program-src frag-src))))
(gl-compile-shader fs)
;; 真正代码还要：(when (zero? (gl-get-shader-iv vs gl-compile-status)) …取 info log…)

;; 2. 链接 program
(define prog (gl-create-program))
(gl-attach-shader prog vs)
(gl-attach-shader prog fs)
(gl-link-program prog)

;; 3. 上传 VBO：data 是 f32vector（这里是顶点坐标的扁平数组）
(define vbo (u32vector-ref (gl-gen-buffers 1) 0))
(gl-bind-buffer gl-array-buffer vbo)
(gl-buffer-data gl-array-buffer (gl-vector-sizeof data) data gl-static-draw)

;; 4. 建 VAO / 描述属性
(define vao (u32vector-ref (gl-gen-vertex-arrays 1) 0))
(gl-bind-vertex-array vao)
(gl-vertex-attrib-pointer 0 3 gl-float #f 0 0)
(gl-enable-vertex-attrib-array 0)

;; 5. 绘制
(gl-use-program prog)
(gl-bind-vertex-array vao)
(gl-draw-arrays gl-triangles 0 3)

上面的骨架省略了检查。真实代码在编译、链接之后都要问 GL「成功了没有、失败为什么」，用到的是这一组查询：

查询 API 的规律它们不改状态、不绘制，只读。命名是 gl-get-<对象>-<要什么>：-iv 表示「取一个整数」，-info-log 取文本；参数几乎都是「对象 id + 一个枚举，说明你想问哪一项」；取字符串的那几个返回「长度 + 内容」两个值。

完整带状态检查、info log、失败清理的 raw 版本就是 compare/raw-triangle.rkt。

第一次读 raw 骨架觉得信息量大，很正常。可以先跳到 2.1 把便利层版本跑通，知道「每个便利函数背后大概做什么」之后再回来对照；不需要一次记住所有 gl-*。

本课代码为了把注意力放在「VBO / VAO / program 各自是什么」上，使用了便利层；每一个便利调用都只是上面某几步的组合：

2.1 顶点数据

GPU 画一个三角形，是从一串顶点开始的。这一节要搭的三样东西——存顶点数据的 VBO、记「怎么读」的 VAO、GPU 上的程序 program——先把它们的关系摆出来，后面逐节展开。

先说数据本身。一个顶点至少要有位置，位置就是一个三维坐标 (x y z)。

用的坐标不是屏幕像素，而是标准坐标（normalized device coordinates）：x、y 都在 -1 到 1 之间，窗口中心是 (0, 0)，右上角是 (1, 1)，左下角是 (-1, -1)。超出这个范围的顶点会被裁掉，画不到窗口里。

02-hello-triangle/triangle.rkt源码 ↗
;; 三个顶点。一个顶点至少要有位置；vec-3 = 三个 float = (x y z)。
;; 坐标是标准坐标（-1..1，中心 0）。vec-array 把三个顶点打包成一条连续缓冲。
(define vertices
  (vec-array (vec-3 -0.5 -0.5 0.0)     ; 左下
          (vec-3  0.5 -0.5 0.0)     ; 右下
          (vec-3  0.0  0.5 0.0)))   ; 上中

vec-3 是 racket-shader 提供的类型，一个 vec-3 就是三个 float。vec-array 把这些顶点按顺序打包成一条连续缓冲，所以内存里是紧挨着的一串 x y z：

这里的 vec-array 是值层便利，不是 OpenGL 便利：它内部就是 f32vector。raw 写法可以直接写 (f32vector -0.5 -0.5 0.0 …)，上传时再用 gl-vector-sizeof 算字节数。它只负责组织 CPU 数据，不涉及 GL 状态。

一个顶点 12 字节，三个顶点 36 字节——这个数字下一步上传到 GPU 时要用。

2.2 把数据搬进显存：VBO

本节开始用便利层：buffer-new 对应 gl-gen-buffers，buffer-upload 对应 gl-buffer-data + 字节数计算。raw 三步见 2.0。

上一步的 vertices 还在 CPU 内存里，GPU 读不到。要在显存里开一块缓冲（vertex buffer object，VBO）把数据拷进去，三步：

  1. buffer-new 让 OpenGL 生成一个缓冲 id（内部就是 gl-gen-buffers）；裸写法是 (u32vector-ref (gl-gen-buffers 1) 0)。
  2. gl-bind-buffer gl-array-buffer vbo 把这块缓冲绑到「顶点数据」（C 里叫 GL_ARRAY_BUFFER）这个目标上；
  3. buffer-upload 在显存里按字节数申请空间，把数据拷进去；裸写法是 (gl-buffer-data target (gl-vector-sizeof data) data usage)，其中 data 要先 (vec-array-data vertices) 取出、字节数还要自己算——这两步由 buffer-upload 包掉。

这三步写在 init 里，init 只在窗口第一次绘制、GL 上下文就绪后跑一次。注意 vbo 是文件顶部 (define vbo 0) 声明的，这里只是 set! 它——为什么提到顶层，2.9 讲（关窗时要用它来删）。

02-hello-triangle/triangle.rkt源码 ↗
  ;; ② 把顶点数据搬进显存。
  ;;    这一步只依赖 gl-array-buffer 这个绑定，和 VAO 无关（VAO 没绑也能上传）。
  ;;    buffer-new：生成一个缓冲 id（= gl-gen-buffers(1) 的便利封装）。
  (set! vbo (buffer-new))
  ;; gl-bind-buffer(目标, id)：把这块缓冲绑到“顶点数据”目标上。
  ;;   gl-array-buffer 是 OpenGL 内置常量（C 里叫 GL_ARRAY_BUFFER），表示顶点数据用途。
  ;;   其他缓冲目标（UBO/SSBO/像素缓冲…）和用法常量见教程 2.2 的表。
  (gl-bind-buffer gl-array-buffer vbo)
  ;; buffer-upload(目标, 数据, 用法)：申请空间并把数据拷进显存。
  ;;   字节数由 buffer-upload 自动算；gl-static-draw 表示基本不变。
  (buffer-upload gl-array-buffer vertices gl-static-draw)

第一次见 gl-bind-buffer / gl-array-buffer

这两个名字容易混，先分清：一个是函数，一个是常量。

名字是什么在本例里
gl-bind-buffer函数，签名是 (gl-bind-buffer target id)把 vbo 绑到 gl-array-buffer 这个「插槽」上；只改状态，不传数据。id 传 0 表示解绑，但对 EBO 要小心（见 2.7）
gl-array-bufferOpenGL 常量（C 里叫 GL_ARRAY_BUFFER）target 的一种，表示「这块缓冲装的是顶点属性」
vbo教程自己定义的变量一个整数 id，指向显存里那块缓冲；不是 OpenGL 常量

命名规则很机械，记住一条就够：C 常量 GL_XXX_YYY → Racket 常量 gl-xxx-yyy（去掉 GL_、转小写、下划线换连字符）。函数名同理：glBufferData → gl-buffer-data。这些常量本质都是整数（枚举值或位掩码），不是字符串；位掩码可以用 bitwise-ior 组合。glsl-opengl 现在把 opengl 导出的 GL_* 常量全量映射到 gl-*；与函数或 opengl 自带工具撞名时按约定加 var- 前缀（例如 var-version、var-extensions）。新版本 opengl 若增加常量，运行 core/opengl/generate-constants.rkt 重新生成即可。

target 是 OpenGL 的绑定点（binding point），不止 gl-array-buffer 一种。下面这些是常见的缓冲目标，先有张地图，遇到时再查：

这些名字已经收录在 glsl-opengl 的 rename.rkt 里，可以直接写；教程只是暂未展开它们的用法。这里列出来是为了让你知道：gl-array-buffer 不是「缓冲」的唯一形态，以后看到别的 target 不必惊讶。

上传时最后一个参数 gl-static-draw 也有同类常量，叫用法提示（usage hint）。它不改变数据含义，只告诉驱动「这份数据大概多久变一次」，让驱动决定放显存还是内存、怎么缓存：

常量含义典型场景
gl-static-draw（GL_STATIC_DRAW）上传一次，反复画很多次静态模型、地形、本例的三角形
gl-dynamic-draw（GL_DYNAMIC_DRAW）会反复修改，但使用频率不低每帧或偶尔更新的顶点
gl-stream-draw（GL_STREAM_DRAW）几乎每次用都变粒子、每帧重建的临时缓冲

用法提示只是提示，填错不影响画面正确性，最多影响性能；不要把它当成「数据真的不会变」的保证。同一组还有 gl-static-read / gl-dynamic-read / gl-stream-read（回读）和 gl-static-copy / gl-dynamic-copy / gl-stream-copy（buffer 间拷贝），本教程暂未用到。

把视野再放宽一点，OpenGL 常量大致分这几族。看到一个新常量，先判断它属于哪一族，比死记名字有用：

族例子用在哪
shader 阶段gl-vertex-shader、gl-fragment-shadergl-create-shader：这段源码是哪一阶段
缓冲目标gl-array-buffer、gl-element-array-buffergl-bind-buffer / gl-buffer-data：这块缓冲拿来干什么
用法提示gl-static-draw、gl-dynamic-drawgl-buffer-data：数据更新频率
数据类型gl-float、gl-unsigned-short描述顶点分量、索引宽度
图元gl-triangles、gl-lines、gl-triangle-stripgl-draw-*：顶点怎么拼成图元
位掩码gl-color-buffer-bit、gl-depth-buffer-bitgl-clear：清哪些缓冲；可用 bitwise-ior 组合
状态开关 / 查询gl-depth-test、gl-compile-statusgl-enable / gl-get-shader-iv：开状态或查结果

有两处值得停下来看：

  • 这些 gl-* 函数几乎没有「对象」参数，它们只对当前绑在这个目标上的那块缓冲生效——OpenGL 是个状态机，先绑，再操作。比如 buffer-upload 的参数里就没有 vbo，它用的是刚绑上的那块。
  • 裸写法 gl-buffer-data 的第二个参数是字节数，不是 float 的个数：9 个 float 是 36 字节，所以由 buffer-upload 自动算，不要手写 9。（gl-static-draw 是用法提示：这份数据基本不变。）

关键点上传顶点数据只依赖 gl-array-buffer 这一个绑定，和 VAO 没关系：VAO 一个都没建的现在，数据照样能传上去。反过来，VAO 也从来不存顶点数据。

2.3 两段着色器与 program

本节用 build-program；它内部就是 2.0 列的 raw 编译/链接/状态检查。想看完整 raw 版，打开 compare/raw-triangle.rkt。

数据在 GPU 上了，但 GPU 还不知道拿它干什么。真正干活的小程序叫 shader，用 GLSL 写，这一节要两段：

  • 顶点着色器：每个顶点跑一次，算出这个顶点最后落在屏幕的哪个位置。它必须给 gl-position 赋值，别的一概不管。
  • 片元着色器：每个像素跑一次，决定这个像素什么颜色。它必须给自己的 out 变量赋值（这里是 frag-color）。

在 Racket 里，两段着色器各写成一个 glsl 块：

02-hello-triangle/triangle.rkt源码 ↗
;; 顶点着色器：每个顶点跑一次，必须给 gl-position 赋值——顶点最终落在哪。
(define vert-src
  (glsl (version 330 core)
        ;; layout(location = 0) 表示"从 0 号属性槽读"，下面描述顶点格式时要用同一个 0
        (layout (location 0) in vec-3 a-pos)
        (define (main) void
          (set! gl-position (vec-4 a-pos 1.0)))))   ; 补 w=1，凑成 vec-4

;; 片元着色器：每个像素跑一次，必须给 out 变量赋值——像素什么颜色。
(define frag-src
  (glsl (version 330 core)
        (out vec-4 frag-color)
        (define (main) void
          (set! frag-color (vec-4 1.0 0.5 0.2 1.0)))))  ; 橙色

第二行里的 (layout (location 0) in vec-3 a-pos)，那个 0 是属性槽号——「这个属性从 0 号槽读」。下面 2.4 描述顶点格式时要用同一个 0，两边对不上就什么都画不出来。

把两段着色器编译并链接成一个 program，只要一行 build-program。它会检查编译和链接的状态，失败时把报错行给你：

02-hello-triangle/triangle.rkt源码 ↗
  ;; ① 编译两段着色器并链接成一个 program。
  ;;    racket-shader 的工具：自动查编译/链接状态，失败时给出报错行。
  (set! program (build-program (gl-vertex-shader vert-src)
                                              (gl-fragment-shader frag-src)))

关键点(glsl …) 里写的是 S 表达式，不是字符串：racket-shader 在编译期把它翻译成 GLSL 文本。所以像 (version 330 core)、(layout (location 0) in vec-3 a-pos) 这些写法都能被 Racket 检查括号配平，不用手拼字符串。

2.4 VAO：数据说明书

vertex-array-new 对应 gl-gen-vertex-arrays；后面的 gl-vertex-attrib-pointer / gl-enable-vertex-attrib-array 仍然是 raw 调用。

显存里现在有一块缓冲，但 GPU 还不知道里面的字节怎么切：从哪开始、切几个算一个属性、下一个顶点在哪儿。这些「怎么读」的信息打包成一个对象，叫 VAO（vertex array object）。VAO 不存数据，它是一张说明书，记的是「每个属性槽怎么从哪块缓冲、按什么格式读」。

写说明书要四步：vertex-array-new 生成 id → gl-bind-vertex-array 绑定 → gl-vertex-attrib-pointer 描述一个属性槽 → gl-enable-vertex-attrib-array 打开这个槽：

02-hello-triangle/triangle.rkt源码 ↗
  ;; ③ 建 VAO 并绑定，然后描述“怎么读”。这两步才依赖 VAO。
  ;;    VAO = 顶点数组对象，是“数据说明书”，记下每个属性槽怎么从缓冲里读。
  (set! vao (vertex-array-new))
  (gl-bind-vertex-array vao)
  ;; gl-vertex-attrib-pointer(槽号, 分量数, 类型, 归一化, 步长, 偏移)
  ;;   = 0 号槽 / 每顶点 3 个分量 / 类型 float / 不归一化 / 紧密排列(0) / 从 0 开始
  ;;   ★它没有“缓冲”参数，抓的是当前绑在 gl-array-buffer 上的那块（即②的 vbo，仍绑着）。
  (gl-vertex-attrib-pointer 0 3 gl-float #f 0 0)
  ;; 属性槽默认关闭，必须打开；不打开时 shader 读到的是常量 (0,0,0,1)。
  (gl-enable-vertex-attrib-array 0)

gl-vertex-attrib-pointer 的参数最多，逐个拆开看：

参数 本例的值 含义
槽号 0 对应顶点着色器里 (layout (location 0) …) 的 0，两边必须一致
分量数 3 一个顶点在这个属性上有 3 个分量（x y z）
类型 gl-float 每个分量是 32 位 float
是否归一化 #f 不把数据映射到 0..1；数据本来就是 float，保持 #f
步长 0 相邻两个顶点的起始位置差多少字节；0 = 紧密排列，交给 OpenGL 按「分量数 × 类型大小」自己算
偏移 0 这个属性从缓冲区第几个字节开始读

本例就是 0 3 gl-float #f 0 0：0 号槽、每顶点 3 个分量、float、不归一化，因为顶点是紧密排列的，步长和偏移都是 0。

坑gl-vertex-attrib-pointer 的参数表里没有「缓冲」这一项——它记下的源缓冲，就是调用这一刻绑在 gl-array-buffer 上的那块。所以它必须在 VBO 还绑着的时候调；顺序反了，说明书就记成了别的（或者空的）缓冲。

还有，属性槽默认是关着的。不调 gl-enable-vertex-attrib-array，着色器读到的永远是常量 (0,0,0,1)，所有顶点叠在同一个位置上，屏幕上什么都没有。

2.5 哪些状态属于 VAO

VAO 是「当前状态」的一部分：绑定一个 VAO 之后，有些 gl-* 调用改的是这个 VAO 记的东西，有些改的是全局状态。分清这两类，后面代码的顺序就不用死记了。

状态 归谁
每个属性槽的开关、格式、源 VBO 引用 属于当前绑着的 VAO
gl-element-array-buffer 的绑定（EBO） 属于当前绑着的 VAO
gl-array-buffer 的绑定（VBO） 不属于 VAO，是全局状态
当前 program 不属于 VAO，是全局状态
viewport 不属于 VAO，是全局状态
清屏色 不属于 VAO，是全局状态

关键点这张表决定了后面所有代码的顺序：上传顶点数据可以在 VAO 之外做（gl-array-buffer 是全局状态），但绑 EBO 必须在 VAO 绑着的时候做，因为 gl-element-array-buffer 的绑定记在 VAO 里。

2.6 draw：每帧的固定套路

东西都备齐了，剩下的就是每帧重复一遍的固定套路：清屏、挂上要用的对象、发绘制命令、解绑。

02-hello-triangle/triangle.rkt源码 ↗
(define (draw)
  (gl-clear-color 0.10 0.12 0.20 1.0)   ; 设清屏色（只记住，不画）
  (gl-clear gl-color-buffer-bit)        ; 用记住的颜色擦掉颜色缓冲

  (program-use program)             ; 选程序
  (gl-bind-vertex-array vao)        ; 挂上说明书
  ;; gl-draw-arrays(图元, 起始顶点, 顶点数)：触发整条管线
  (gl-draw-arrays gl-triangles 0 3) ; 第 0 个顶点起画 3 个，每 3 个一组三角形
  (gl-bind-vertex-array 0))
  • gl-clear-color 只是把清屏色记进状态，不画任何东西；紧接着的 gl-clear gl-color-buffer-bit 才真的用这个颜色把颜色缓冲擦干净。
  • program-use 选中链接好的 program；gl-bind-vertex-array 挂上说明书，GPU 才知道顶点数据怎么读。
  • gl-draw-arrays(图元, 起始顶点, 顶点数)：从第 0 个顶点开始连续取 3 个顶点，每 3 个一组拼成三角形（gl-triangles）。这一行才真正触发整条渲染管线。

最后 (gl-bind-vertex-array 0) 解绑，免得后面哪段代码误改到它。

2.7 用索引画矩形：EBO

三角形画出来了，换矩形试试。矩形 = 两个三角形 = 6 个顶点，但它只有 4 个角，直接写 6 个顶点就要把其中两个角写两遍。顶点一多这种重复就很浪费，于是有了索引缓冲（element buffer object，EBO）：顶点还是只存 4 个角，另外存一张下标表，告诉 GPU 每次取哪 3 个角拼三角形。

02-hello-triangle/rectangle.rkt源码 ↗
;; 4 个角（顶点只存一份）
(define vertices
  (vec-array (vec-3  0.5  0.5 0.0)     ; 0 右上
          (vec-3  0.5 -0.5 0.0)     ; 1 右下
          (vec-3 -0.5 -0.5 0.0)     ; 2 左下
          (vec-3 -0.5  0.5 0.0)))   ; 3 左上

;; 下标表：告诉 GPU 每次取哪 3 个角拼三角形（(0,1,2) 和 (0,2,3) 共用 0、2）
(define indices (u16-array 0 1 2
                           0 2 3))

下标表里 (0,1,2) 和 (0,2,3) 两个三角形共用 0、2 两个角，所以 4 个角就够了。下标用 u16-array 构造；裸写法就是 ffi 的 (u16vector 0 1 2 0 2 3)——同元素类型、同内存，u16-array 只是命名版并做 0..65535 检查。

上传 EBO 和上传 VBO 几乎一样，只有绑定的目标换成了 gl-element-array-buffer：

02-hello-triangle/rectangle.rkt源码 ↗
  ;; 索引缓冲 EBO。
  ;; ★和 ARRAY_BUFFER 不同：ELEMENT_ARRAY_BUFFER 的绑定是 VAO 状态，
  ;;   所以必须在 VAO 还绑着的时候绑它，VAO 才会记住；画的时候才找得到。
  (set! ebo (buffer-new))
  (gl-bind-buffer gl-element-array-buffer ebo)
  (buffer-upload gl-element-array-buffer indices gl-static-draw)

坑gl-element-array-buffer 的绑定是 VAO 状态（见 2.5 的表），所以绑 EBO 必须在 VAO 还绑着的时候做，VAO 才记得住这块缓冲。画的时候 GPU 是从当前 VAO 里去找索引缓冲的——把这两行挪到 (gl-bind-vertex-array 0) 之后，矩形会整个消失，这是本节最容易踩的坑。反过来，在 VAO 绑着的时候执行 (gl-bind-buffer gl-element-array-buffer 0) 也会把 VAO 里记的 EBO 清掉；真要解绑，先解绑 VAO。

画的时候把 gl-draw-arrays 换成 gl-draw-elements：

02-hello-triangle/rectangle.rkt源码 ↗
  ;; 和 gl-draw-arrays 的区别：不按顺序取顶点，而是按 EBO 里的下标取。
  ;; gl-draw-elements(图元, 索引个数, 索引类型, 索引数据的字节偏移)
  (gl-draw-elements gl-triangles 6 gl-unsigned-short 0)

它的四个参数分别是：图元（gl-triangles）、这次要用几个索引（6，两个三角形各要 3 个下标）、索引类型（gl-unsigned-short，对应 u16-array 的元素类型）、索引数据的字节偏移（0 表示从头）。最后一个参数是字节偏移，不是索引下标：想跳过 3 个 u16 索引，要传 6，不是 3。

2.8 draw-arrays 与 draw-elements

两个绘制函数的区别只在「顶点从哪来」：

函数 顶点从哪来 什么时候用
gl-draw-arrays 从起始顶点开始，按顺序连续取给定个数 顶点不重复，每个顶点只属于一个三角形
gl-draw-elements 按 EBO 里的下标取，取几个由参数给 有共享顶点，用 EBO 省下重复的顶点数据

2.9 谁拥有这些对象：GPU 资源要显式释放

本课创建了三样东西：一个 program、一个 VBO、一个 VAO（矩形课再加一个 EBO）。它们和 vertices 那种 Racket 值不是一类东西：

东西住在哪谁回收
vertices / vec-array / vec-3Racket 堆Racket GC，自动
program / vbo / vao / ebo / 纹理显卡（驱动管的显存与状态）只能自己调 gl-delete-*

分隔这两栏的是 buffer-upload：它把字节复制进显存（glBufferData 的语义就是一次性拷贝），复制完 Racket 那份就可以被 GC 收走——所以 vec-array 这类值永远不需要你手动释放。但从这一刻起数据住在 VBO 里，而 VBO 是一个 GPU 侧对象：你手里只有一个整数 id，Racket 堆里没有任何对象「指向」它，GC 也就看不见它、永远不会替你回收。

关键点句柄归调用方：谁 buffer-new / vertex-array-new / texture-new / build-program，谁负责 buffer-delete / vertex-array-delete / texture-delete / program-delete。不删不会立刻报错，只会一直占着显存，直到进程退出、上下文销毁才整批还给驱动。

为什么不能让 GC 或 Racket 终结器代劳：删除必须发生在拥有这个上下文的线程上，而且要在上下文还活着的时候；终结器跑在 GC 线程、时机不确定，还可能撞上 GPU 正在跑的 draw——轻则状态错误，重则崩溃。所以 racket-shader-opengl 一律返回裸句柄、不挂终结器（见它自己的 DESIGN.md §3.1）。

2.9.1 写法：把句柄提到顶层，关窗时删

要在关窗时删，就得让「关窗那一刻」能看到这些句柄。所以本课把 vbo 也提到了顶层（和 program / vao 一样），初始值写 0：

(define program 0)   ; 编译链接好的着色器程序
(define vao 0)       ; "说明书"：记录顶点数据怎么读
(define vbo 0)       ; 0 = 还没创建

(define (init)
  (set! program (build-program ...))
  (set! vbo (buffer-new))
  ...
  (set! vao (vertex-array-new)))

为什么用 0 而不是 #f：GL 的 delete 规定「名字 0 不是对象，忽略」，所以 init 半途失败、句柄还是 0 时，关窗也能安全地跑一遍删除。然后写一个 shutdown，里面就是最直接的几个 *-delete：

;; 关窗前释放：这些句柄归调用方，不删就一直占着显存
(define (shutdown)
  (gl-bind-vertex-array 0)      ; 先解绑，别删正在用的
  (gl-use-program 0)
  (vertex-array-delete vao)
  (buffer-delete vbo)
  (program-delete program))

(make-window #:title "02 第一个三角形"
             #:init init
             #:draw draw
             #:on-close shutdown)   ; 关窗时、上下文还活着，跑一次 shutdown

顺序不是随意的：先解绑当前状态，再删引用方（VAO 记着 buffer 的引用）→ 缓冲 → 纹理 → program。几个要注意的点：

  • 删除是「标记待删」。驱动可能还在等正在跑的 draw 用完，真正释放晚一点——所以删完别再拿这个 id 用。
  • 解绑不等于删除。(gl-bind-buffer gl-array-buffer 0) 只是把「当前绑定」清掉，那块缓冲还在显存里。
  • build-program 已经把中间的 shader 对象自己删掉了（链接完就没用了），所以真正要你管的只有 program 本身。

什么时候会真漏教程每课只 init 一次、关窗就 (exit 0)，所以即使不删也看不出毛病。但下面这些场景会真漏：着色器/纹理热重载（每编一次漏一个 program）、上下文丢失或重建、一个进程开多个窗口、把 init 放在可重复触发的位置。养成「分配了就想着谁删」的习惯，这些场景就不必回头重写。

对象变多了怎么办后几课会有 4 个 program、十来个缓冲，shutdown 里就是十几行 *-delete——这是最直白的写法，也最好查：谁创建的一眼能对上谁删除的。真到几十上百个对象时，再考虑「分配时登记、退出时统一排空」的登记表（racket-shader-opengl 的 DESIGN.md §3.1 讨论的正是这件事），那是优化，不是入门必需。

02-hello-triangle/triangle.rkt，画一个橙色三角形。这是 2.0 讲的便利层版本；raw 流程见 2.0 的骨架和 compare/raw-triangle.rkt：

02-hello-triangle/triangle.rkt源码 ↗
#lang glsl-opengl
;; ============================================================
;; 02 · 第一个三角形
;; 运行：racket 02-hello-triangle/triangle.rkt
;; 上一课：01-window/window.rkt
;; ============================================================
;; 目标：把三个顶点变成屏幕上的三角形。顺序是
;;   顶点数据 → VBO（显存）→ 两段着色器 → program → VAO → 发绘制命令
;; 下面按这个顺序写，走到哪讲到哪。
;;
;; 阅读顺序：先看教程 2.0 的 raw OpenGL 流程（以及 compare/raw-triangle.rkt），
;; 理解 shader 编译、buffer 上传、VAO 属性描述分别对应哪些 gl-* 调用；
;; 本文件为了聚焦概念，使用 racket-shader-opengl 的便利层（build-program / buffer-new …）。

(require racket/class
         "../lib/window.rkt")

;; 三个顶点。一个顶点至少要有位置；vec-3 = 三个 float = (x y z)。
;; 坐标是标准坐标（-1..1，中心 0）。vec-array 把三个顶点打包成一条连续缓冲。
(define vertices
  (vec-array (vec-3 -0.5 -0.5 0.0)     ; 左下
          (vec-3  0.5 -0.5 0.0)     ; 右下
          (vec-3  0.0  0.5 0.0)))   ; 上中

;; 顶点着色器：每个顶点跑一次，必须给 gl-position 赋值——顶点最终落在哪。
(define vert-src
  (glsl (version 330 core)
        ;; layout(location = 0) 表示"从 0 号属性槽读"，下面描述顶点格式时要用同一个 0
        (layout (location 0) in vec-3 a-pos)
        (define (main) void
          (set! gl-position (vec-4 a-pos 1.0)))))   ; 补 w=1，凑成 vec-4

;; 片元着色器：每个像素跑一次，必须给 out 变量赋值——像素什么颜色。
(define frag-src
  (glsl (version 330 core)
        (out vec-4 frag-color)
        (define (main) void
          (set! frag-color (vec-4 1.0 0.5 0.2 1.0)))))  ; 橙色

(define program 0)   ; 编译链接好的着色器程序
(define vao 0)       ; "说明书"：记录顶点数据怎么读
;; 这些缓冲句柄也放在顶层：关窗时 shutdown 要能拿到（0 = 还没创建）
(define vbo 0)

;; init 只跑一次（窗口第一次绘制、GL 上下文就绪后）。
(define (init)

  ;; ① 编译两段着色器并链接成一个 program。
  ;;    racket-shader 的工具：自动查编译/链接状态，失败时给出报错行。
  (set! program (build-program (gl-vertex-shader vert-src)
                               (gl-fragment-shader frag-src)))

  ;; ② 把顶点数据搬进显存。
  ;;    这一步只依赖 gl-array-buffer 这个绑定，和 VAO 无关（VAO 没绑也能上传）。
  ;;    gl-gen-buffers(n)：生成 n 个缓冲，返回装 id 的向量；
  ;;    裸写法： (u32vector-ref (gl-gen-buffers 1) 0)
  ;;    buffer-new：取单个缓冲 id（= glGenBuffers(1) 的便利封装）。
  (set! vbo (buffer-new))
  ;; gl-bind-buffer(目标, id)：把这块缓冲绑到“顶点数据”目标上。
  ;;   gl-array-buffer 是 OpenGL 内置常量（C 里叫 GL_ARRAY_BUFFER），表示顶点数据用途。
  ;;   其他缓冲目标（UBO/SSBO/像素缓冲…）和用法常量见教程 2.2 的表。
  (gl-bind-buffer gl-array-buffer vbo)
  ;; buffer-upload(目标, 数据, 用法)：申请空间并把数据拷进显存。
  ;;   数据直接给 vec-array/ffi 向量；gl-static-draw 表示基本不变。
  ;;   裸写法： (gl-buffer-data gl-array-buffer
  ;;                            (gl-vector-sizeof data)   ; 字节数
  ;;                            data                      ; 裸 ffi 向量
  ;;                            gl-static-draw)
  ;;   —— 需先 (vec-array-data vertices) 取 data、再算字节；buffer-upload 把这两步包起来。
  (buffer-upload gl-array-buffer vertices gl-static-draw)

  ;; ③ 建 VAO 并绑定，然后描述“怎么读”。这两步才依赖 VAO。
  ;;    VAO = 顶点数组对象，是“数据说明书”，记下每个属性槽怎么从缓冲里读。
  (set! vao (vertex-array-new))
  (gl-bind-vertex-array vao)
  ;; gl-vertex-attrib-pointer(槽号, 分量数, 类型, 归一化, 步长, 偏移)
  ;;   = 0 号槽 / 每顶点 3 个分量 / 类型 float / 不归一化 / 紧密排列(0) / 从 0 开始
  ;;   ★它没有“缓冲”参数，抓的是当前绑在 gl-array-buffer 上的那块（即②的 vbo，仍绑着）。
  (gl-vertex-attrib-pointer 0 3 gl-float #f 0 0)
  ;; 属性槽默认关闭，必须打开；不打开时 shader 读到的是常量 (0,0,0,1)。
  (gl-enable-vertex-attrib-array 0)

  (gl-bind-vertex-array 0))   ; 解绑，避免后面误改

;; 【哪些东西属于 VAO】
;;   VAO 状态：每个属性的 开关/格式/源 VBO 引用；ELEMENT_ARRAY_BUFFER 绑定。
;;   全局状态（不属于 VAO）：ARRAY_BUFFER 绑定、当前 program、viewport 等。
;;   所以上传数据不依赖 VAO；只有 attrib-pointer / enable / 绑 EBO 才依赖。

;; draw 每帧跑一次。这里只是"挂上要用的东西，然后画"。
(define (draw)
  (gl-clear-color 0.10 0.12 0.20 1.0)   ; 设清屏色（只记住，不画）
  (gl-clear gl-color-buffer-bit)        ; 用记住的颜色擦掉颜色缓冲

  (program-use program)             ; 选程序
  (gl-bind-vertex-array vao)        ; 挂上说明书
  ;; gl-draw-arrays(图元, 起始顶点, 顶点数)：触发整条管线
  (gl-draw-arrays gl-triangles 0 3) ; 第 0 个顶点起画 3 个，每 3 个一组三角形
  (gl-bind-vertex-array 0))

;; ------------------------------------------------------------
;; 关窗前释放：这些句柄归调用方，不删就一直占着显存
;; ------------------------------------------------------------
;; 顺序：先解绑当前状态，再删引用方（VAO）→ 缓冲 → 纹理 → program。
;; 初始值是 0：0 不是有效对象，GL 的 delete 会忽略它（init 没跑完也能安全关窗）。
(define (shutdown)
  (gl-bind-vertex-array 0)      ; 别删正在用的
  (gl-use-program 0)
  (vertex-array-delete vao)
  (buffer-delete vbo)
  (program-delete program))

(define-values (frame canvas)
  (make-window #:title "02 第一个三角形"
               #:init init
               #:draw draw
               #:on-close shutdown))
(send frame show #t)

;; 复盘：VBO 存数据，VAO 记"怎么读"，program 是 GPU 上的程序，draw 用它们画图。
;; 规律：先绑，再操作；尺寸用字节数；槽号两边要对齐，属性槽要先 enable。

02-hello-triangle/rectangle.rkt，用索引画一个蓝色矩形：

02-hello-triangle/rectangle.rkt源码 ↗
#lang glsl-opengl
;; ============================================================
;; 02 · 用索引画一个矩形（EBO）
;; 运行：racket 02-hello-triangle/rectangle.rkt
;; 上一课：02-hello-triangle/triangle.rkt
;; ============================================================
;; 上一课用 3 个顶点画三角形。矩形 = 两个三角形 = 6 个顶点，但只有 4 个角。
;; 直接写 6 个顶点会重复两个角。用索引缓冲（EBO）只存 4 个角 + 一张下标表。
;; 和上一课的差别只有两处：多上传一个 EBO，画的时候换成 gl-draw-elements。
;; 本文件继续使用 02.0 介绍的便利层；raw 等价物见教程 2.0 的对照表。

(require racket/class
         "../lib/window.rkt")

;; 两段着色器：和上一课一样，只是颜色换成蓝色
(define vert-src
  (glsl (version 330 core)
        (layout (location 0) in vec-3 a-pos)
        (define (main) void
          (set! gl-position (vec-4 a-pos 1.0)))))

(define frag-src
  (glsl (version 330 core)
        (out vec-4 frag-color)
        (define (main) void
          (set! frag-color (vec-4 0.2 0.7 1.0 1.0)))))

;; 4 个角（顶点只存一份）
(define vertices
  (vec-array (vec-3  0.5  0.5 0.0)     ; 0 右上
          (vec-3  0.5 -0.5 0.0)     ; 1 右下
          (vec-3 -0.5 -0.5 0.0)     ; 2 左下
          (vec-3 -0.5  0.5 0.0)))   ; 3 左上

;; 下标表：告诉 GPU 每次取哪 3 个角拼三角形（(0,1,2) 和 (0,2,3) 共用 0、2）
;; 裸写法： (u16vector 0 1 2 0 2 3)（ffi/vector）。
;; u16-array 是它的命名版：同元素类型、同内存，额外做 0..65535 检查。
(define indices (u16-array 0 1 2
                           0 2 3))

(define program 0)
(define vao 0)
;; 这些缓冲句柄也放在顶层：关窗时 shutdown 要能拿到（0 = 还没创建）
(define vbo 0)
(define ebo 0)

(define (init)
  (set! program (build-program (gl-vertex-shader vert-src)
                               (gl-fragment-shader frag-src)))

  ;; 顶点数据上传：只依赖 gl-array-buffer 这个绑定，和 VAO 无关
  (set! vbo (buffer-new))
  (gl-bind-buffer gl-array-buffer vbo)
  (buffer-upload gl-array-buffer vertices gl-static-draw)

  ;; 建 VAO、描述位置属性（这两步依赖 VAO）
  (set! vao (vertex-array-new))
  (gl-bind-vertex-array vao)
  (gl-vertex-attrib-pointer 0 3 gl-float #f 0 0)
  (gl-enable-vertex-attrib-array 0)

  ;; 索引缓冲 EBO。
  ;; ★和 ARRAY_BUFFER 不同：ELEMENT_ARRAY_BUFFER 的绑定是 VAO 状态，
  ;;   所以必须在 VAO 还绑着的时候绑它，VAO 才会记住；画的时候才找得到。
  (set! ebo (buffer-new))
  (gl-bind-buffer gl-element-array-buffer ebo)
  (buffer-upload gl-element-array-buffer indices gl-static-draw)

  (gl-bind-vertex-array 0))

(define (draw)
  (gl-clear-color 0.10 0.12 0.20 1.0)
  (gl-clear gl-color-buffer-bit)

  (program-use program)
  (gl-bind-vertex-array vao)
  ;; 和 gl-draw-arrays 的区别：不按顺序取顶点，而是按 EBO 里的下标取。
  ;; gl-draw-elements(图元, 索引个数, 索引类型, 从第几个索引开始)
  (gl-draw-elements gl-triangles 6 gl-unsigned-short 0)
  (gl-bind-vertex-array 0))

;; ------------------------------------------------------------
;; 关窗前释放：这些句柄归调用方，不删就一直占着显存
;; ------------------------------------------------------------
;; 顺序：先解绑当前状态，再删引用方（VAO）→ 缓冲 → 纹理 → program。
;; 初始值是 0：0 不是有效对象，GL 的 delete 会忽略它（init 没跑完也能安全关窗）。
(define (shutdown)
  (gl-bind-vertex-array 0)      ; 别删正在用的
  (gl-use-program 0)
  (vertex-array-delete vao)
  (buffer-delete vbo)
  (buffer-delete ebo)
  (program-delete program))

(define-values (frame canvas)
  (make-window #:title "02 矩形（索引绘制）"
               #:init init
               #:draw draw
               #:on-close shutdown))
(send frame show #t)

试试看

  1. 把 triangle.rkt 片元着色器里的 (vec-4 1.0 0.5 0.2 1.0) 改成 (vec-4 0.2 0.9 0.4 1.0)（前三个数依次是红、绿、蓝）→ 三角形从橙色变成绿色。
  2. 给三角形加第四个顶点 (vec-3 0.5 0.5 0.0)，同时把 gl-draw-arrays 的第三个参数从 3 改成 4 → 会看到一个缺了一角的四边形：gl-draw-arrays 只会顺序每 3 个拼一个三角形，多出来的第 4 个顶点没人和它配对。缺的这个角正好由下一节的 EBO 补上。
  3. 把 rectangle.rkt 里绑 EBO 的两行（gl-bind-buffer gl-element-array-buffer 和它下面的 buffer-upload）移到 (gl-bind-vertex-array 0) 之后 → 矩形整个消失，只剩清屏色；移回原位又出现。
  4. 把 indices 改成 (u16-array 0 1 2 1 2 3) → 第一个三角形不变，第二个变成由 1、2、3 三个角拼成：画出来缺的是上半部分中间那一块（左上角、右上角和中心围成的三角形）。

小结

概念 一句话
VBO 显存里那块存顶点数据的缓冲
VAO 说明书：每个属性槽怎么从哪块缓冲、按什么格式读；它本身不存数据
EBO 存下标的缓冲，让多个三角形共用同一批顶点
缓冲目标（target） gl-bind-buffer 的 target 参数指定这块缓冲的用途；gl-array-buffer 只是其中一种
用法提示（usage） gl-static-draw 等，告诉驱动数据更新频率；只影响性能，不影响正确性
program 编译链接好的着色器程序，真正在 GPU 上跑的东西
属性槽 顶点属性的编号（本例是 0 号），着色器用 layout(location …) 跟它对上
标准坐标 顶点位置的坐标范围是 -1..1，中心是 0，超出会被裁掉
GPU 资源 program / VBO / VAO / EBO / 纹理都在 GPU 侧，GC 不收；在 shutdown 里显式 *-delete，关窗时由 #:on-close 触发

对照：不用 racket-shader

compare/raw-triangle.rkt 是同一个三角形只用 opengl 包写的版本：着色器只能写成裸 GLSL 字符串，compile-shader 和 link-program 要自己手写（还得自己检查编译链接状态），连窗口骨架都得再抄一遍。把它和 triangle.rkt 对着读，就知道 racket-shader 把哪些样板收进了 DSL。

三个顶点怎么变成一片像素本节只走到 gl-draw-arrays；后面的图元装配、光栅化、深度测试由 GPU 固定管线完成，代码里看不见。想看清这几步，复习 04 · 用 CPU 走一遍渲染管线 用 Racket 把它们完整写了一遍。
