基础光照

本节目标：在 08 课「物体色 × 光色」那条乘法上补进「方向」——逐片元算 ambient（环境光）、diffuse（漫反射）、specular（镜面高光）三项。为此第一次给顶点加一条法线属性，第一次用「法线矩阵」把法线正确地搬进世界空间，也第一次用 shader-struct 描述顶点布局。跑起来应该看到一个橙色立方体：正面被照亮、中央有一块圆形高光，左侧和底面只剩一点环境光、明显比背景还暗——三项光照同时在场。

$ racket 09-basic-lighting/basic-lighting.rkt

计算位置本课的 Phong 公式在片元着色器里逐像素算。9.1.5 先用 CPU 对三个采样点算一遍，看到数字后再看 9.3 的 shader；CPU 也可以逐顶点算（Gouraud）或离线烘焙成 lightmap，三种位置的取舍见 R3。

9.1 三项各管什么

08 课的一条乘法回答了「颜色从哪来」，但它对方向一无所知：同一份光照参数下，立方体六个面一样亮——因为 u-object-color * u-light-color 里没有任何一项和「面朝哪、光在哪」有关。现实里同一盏灯下，正对灯的面亮、背对灯的面暗、打磨光滑的表面还有一块高光。这三件事各由一项负责，合起来就是常说的「Phong 光照」：

  • ambient（环境光）——保底亮度。现实里光会在墙面、地面之间来回弹，多少总能漏一点到背光面；不去模拟这种反弹，直接给一个常数 0.1。少了它，背光面是纯黑，看着不像真实世界。
  • diffuse（漫反射）——面朝着光的那一部分。亮度正比于「法线 n」与「指向光源的方向 l」夹角余弦，也就是 max(dot(n, l), 0.0)：正对光时是 1，斜着变暗，背向光时为负——max 把负数截成 0，背光面就一点都不漫反射。
  • specular（镜面高光）——反射光正对着眼睛时的亮点。把 l 关于法线做镜像得到反射方向 r（代码里写 reflect(-light-dir, norm)），再看「指向眼睛的方向 v」和 r 有多贴合：pow(max(dot(v, r), 0.0), 32.0)。指数 32 决定高光的松紧——越大越像镜面上的一点，越小越像磨砂面的一大片。

r 是 l 关于法线的镜像（图中画成虚线，表示它是算出来的、不是真实存在的光线）。注意作图时 r 和 v 通常并不重合——那样的像素就没有高光；本课立方体正面中央恰好让两者对上了，于是那里浮出一块亮斑。

三项是同一份光的三种去处，所以最后相加、再乘上 08 课的光色和物色：(ambient + diff + spec) * u-light-color * u-object-color。08 课那条乘法没有被丢掉，只是现在「光有多少」不再是常数，而是逐像素算出来的。

场景里还画了一个白色小方块当「灯」：位置就是 u-light-pos、scale 0.2，片元只输出光色不做乘法——和 08 课一样另起一个 program，因为灯是光本身，不是被光照到的东西。注意本课这个机位下（相机在 (0,0,3)、光在 (1.2,1.0,2.0)）灯落在画面右上方之外，看不见；这不影响光照——u-light-pos 只是个给片元算方向用的坐标，光不必出现在画面里才能照亮物体。

9.1.1 点积到底算出了什么

光照公式里到处是 dot，它不是魔法，就是两个向量的点积：

dot(a, b) = |a| · |b| · cos(θ)

如果 a、b 都已经归一化（长度 1），那么 |a| = |b| = 1，点积就直接等于夹角的余弦：

dot(normalize(a), normalize(b)) = cos(θ)

所以光照里先做 normalize 再 dot，是为了让结果落在 -1 .. 1 之间，直接当「方向有多贴合」用。本课的四个方向都是单位向量：

  • n = normalize(v-normal)：表面法线，垂直表面向外；
  • l = normalize(u-light-pos - v-frag-pos)：从片元指向光源；
  • v = normalize(u-view-pos - v-frag-pos)：从片元指向相机；
  • r = reflect(-l, n)：l 关于法线的反射方向。

注意 l 的符号：它必须是「从表面指向光源」，不是「光传播的方向」。如果写成 lightPos - fragPos，正对光时 dot(n,l)=1；写成反方向就会在最亮的地方得到负值，整块反而变黑。

9.1.2 Lambert 漫反射：为什么是 max(dot(n,l), 0)

漫反射的物理直觉是：一束光打在表面上，表面越正对光，单位面积接收到的能量越多；斜着擦过时，同样的光摊到更大的面积上，单位面积就暗。这个「正对程度」正好是法线和光线方向的夹角余弦：

lambert = max(dot(n, l), 0)

为什么要有 max(..., 0)：当 n 和 l 夹角超过 90° 时，点积是负数，表示光在表面背面。背面不应该被这盏灯照亮，所以把负数截成 0。没有这个 max，背光面会被加上负光，颜色可能被减成黑色甚至出现奇怪的负值。

dot(n,l)夹角max(...,0)视觉效果
1.00°1.0正对光，最亮
0.7≈45°0.7斜着照，变暗
0.090°0.0光擦着表面，漫反射为 0
-0.5≈120°0.0背光面，这盏灯不贡献漫反射

所以漫反射项是：

diffuse = max(dot(n, l), 0) · lightColor · objectColor

9.1.3 Phong 高光：反射方向与眼睛方向

高光不是「表面越亮越白」，而是「反射光正好射进眼睛」。所以要看两个方向有多贴合：

  • r：入射光 l 打到表面后弹开的方向；
  • v：从片元指向眼睛的方向。

反射公式是：

r = 2 · dot(n, l) · n - l

GLSL 的 reflect(I, N) 要求的 I 是「入射方向」，也就是从光源指向表面的方向，正好是 -l。所以代码写成：

09-basic-lighting/basic-lighting.rkt：高光的方向源码 ↗
(vec-3 reflect-dir (reflect (- light-dir) norm))
        (vec-3 view-dir (normalize (- u-view-pos v-frag-pos)))
        (float spec (* (pow (max (dot view-dir reflect-dir) 0.0) 32.0) 0.5))

dot(v, r) 越接近 1，说明眼睛越接近反射光的方向，高光越亮。外面再套一个 pow(..., shininess)：

specular = pow(max(dot(v, r), 0), shininess) · specularStrength

shininess 控制高光的「紧」：指数越大，只有 v 和 r 非常接近时才明显，高光变成一个小点；指数越小，高光摊成一大片，像磨砂表面。max(...,0) 同样是把背向反射方向的负值截掉。

dot(v,r)pow(..., 32)含义
1.01.0眼睛正好在反射方向上，高光最强
0.95≈0.19稍微偏一点，高光迅速衰减
0.8≈0.0008已经基本看不到高光
≤00眼睛在反射方向的背面，没有高光

9.1.4 三项相加：同一份光的三种去处

把三项写在一起：

ambient = 0.1

diffuse = max(dot(n, l), 0)

specular = pow(max(dot(v, r), 0), 32) · 0.5

color = (ambient + diffuse + specular) · lightColor · objectColor

为什么是相加：这三项描述的是同一份光的不同去向——一部分被均匀散射（ambient 的简化替代）、一部分按 Lambert 漫反射、一部分按镜面方向反射。最后再乘 08 课的光色和物体色，08 课那条乘法没有消失，只是「光有多少」从常数变成了逐像素计算。

这只是 Phong 光照模型：它是经验公式，不是严格物理。ambient 是常数，diffuse/specular 也没有能量守恒。它的价值是：公式短、每一项都能单独观察和调参，适合作为理解光照的第一步。后面更物理的模型（如 Cook-Torrance）会保留同样的「法线、光方向、视线、反射」这些几何量，只是换掉 BRDF。

9.1.5 先在 CPU 上算三个点

公式齐了，先别急着写 shader。把 09 课的场景参数拿到 CPU 上，用同一个 phong 函数算三个片元，数字会告诉你每一项到底在做什么。

下面代码里的 vec-3 / vnormalize / vsub / vdot 来自 #lang glsl（racket-shader），不是 racket/math；racket/math 只提供 degrees->radians。

$ racket 09-basic-lighting/phong-cpu.rkt
09-basic-lighting/phong-cpu.rkt（和 frag-src 逐字相同）源码 ↗
(define (phong frag-pos normal)
  (define norm (vnormalize normal))
  (define light-dir (vnormalize (vsub light-pos frag-pos)))
  (define view-dir (vnormalize (vsub eye-pos frag-pos)))
  (define reflect-dir (vreflect (vneg light-dir) norm))

  (define ambient 0.1)
  (define diff (max (vdot norm light-dir) 0.0))
  (define spec (* (expt (max (vdot view-dir reflect-dir) 0.0) 32.0) 0.5))
  (define color (vmul (vmul light-color (+ ambient diff spec)) object-color))
  (list norm light-dir reflect-dir ambient diff spec color))

脚本还顺手做了顶点着色器那两步：v-frag-pos = model · vec4(local-pos, 1)、v-normal = normal-matrix · local-normal。算出来的结果：

采样点v-normaldiffusespecularcolor
正面中央 (0.25, 0.21, 0.94) 0.918 0.499 (1.52, 0.76, 0.47)
正面右上 (0.25, 0.21, 0.94) 0.997 0.002 (1.10, 0.55, 0.34)
左面中央 (−0.97, 0, 0.26) 0.000 0.000 (0.10, 0.05, 0.03)

三行数字正好对应本课想让你看到的三种情况：

  • 正面中央：漫反射接近 1，而且 v 和 r 几乎重合，高光 specular 接近最大值 0.5——这就是画面中央那块亮斑。
  • 正面右上：法线一样、漫反射甚至更高（0.997），但高光掉到 0.002。因为这一点的反射方向 r 不再对着眼睛；高光只看方向，不看「正不正对光」。
  • 左面中央：dot(n,l) < 0，漫反射被 max(...,0) 截成 0，高光也为 0，只剩 ambient × objectColor。背光面不是黑色，是因为环境光保底。

同一个公式，两种执行方式CPU 脚本只算 3 个点，片元着色器对屏幕上每一个像素算一次。09 课的画面是 800×600，立方体覆盖的每个像素都跑了一遍上面这段 phong。这就是 R3 和 R4 反复说的「同一公式、不同计算位置」。

9.2 法线为什么要 inverse-transpose

diffuse 和 specular 全靠法线，所以本课做两件新事：让顶点带上法线（属性 location 1），再把法线从「面自己的坐标」搬进世界空间——它得跟着 model 一起转。这里有个经典坑：法线不能拿 model 矩阵直接转。

顶点位置是「点」，随模型的缩放、旋转、平移怎么变都行；法线是「方向」，它垂直于表面，变换之后必须仍然垂直。model 只含旋转和平移时直接乘没问题；一旦含非等比缩放，两者就分道扬镳：把球在 x 方向拉长 1.5 倍压成椭球，垂直于原来表面的法线若也被拉长 1.5 倍，就不再垂直于拉长后的表面了——光照会照着「想象中的球」算，可表面早就不是那个球。正确做法是「左上 3×3 的逆转置」transpose(inverse(mat-3(model)))：逆先抵消缩放的歪曲，再转置回法线该在的方向。lib/matrix.rkt 里就是这个：

lib/matrix.rkt：m-normal-matrix源码 ↗
;; 法线矩阵：法线要跟着模型转，但不能直接拿 mat-3(model) 去转——模型含非等比缩放时，
;; 顶点被压扁、法线却还指着原方向，光照就错（球会被照成椭球的样子）。
;; 正确的变换是「左上 3x3 的逆转置」：逆抵消缩放的歪曲，再转置回法线该在的方向；
;; 纯旋转 + 等比缩放时逆与转置互相抵消，退化成 mat-3(model)。法线是方向（w=0），平移影响不到它。
(define (m-normal-matrix m)
  (define (e col row) (mat4-ref m col row))
  (mat3-transpose
   (mat3-inverse
    (mat-3 (e 0 0) (e 0 1) (e 0 2)
          (e 1 0) (e 1 1) (e 1 2)
          (e 2 0) (e 2 1) (e 2 2)))))

算出来是个 mat-3，用 (uniform-set! obj-u-normal-matrix-loc 'mat-3 (m-normal-matrix model)) 上传；uniform-set! 按类型符号选 gl-uniform-matrix-3fv，并把转置参数固定成 #f——和 4×4 矩阵同一个理由：本教程的矩阵一律列主序，正好是 GL 期望的排布，再让 GL 转一次反而会转错。顶点着色器里就是一行乘法：

09-basic-lighting/basic-lighting.rkt：上传法线矩阵（draw 里）源码 ↗
  ;; 法线矩阵是 mat-3，uniform-set! 按类型符号选 matrix-3fv，transpose 固定 #f：
  ;; lib/matrix.rkt 的矩阵都是列主序，正好是 GL 要的，传 #t 会让它转错。
  (uniform-set! obj-u-normal-matrix-loc 'mat-3 (m-normal-matrix model))
09-basic-lighting/basic-lighting.rkt：顶点着色器里法线跟着 model 转源码 ↗
        (uniform mat-3 u-normal-matrix)            ; 法线专用的 mat-3，为什么不是 u-model 见 9.2
        (out vec-3 v-normal)
        (out vec-3 v-frag-pos)
        (define (main) void
          (set! v-normal (* u-normal-matrix normal))
          (set! v-frag-pos (vec-3 (* u-model (vec-4 pos 1.0))))
          (set! gl-position (* u-proj (* u-view (* u-model (vec-4 pos 1.0))))))))

关键点model 只含旋转 + 等比缩放时，「逆转置」退化成 mat-3(model)：旋转的逆就是它的转置，等比缩放只是个正数因子、不改方向。所以本课默认画面看不出两者的差别——差别发生在你给 model 加上非等比缩放的那一刻：(m-scale (vec-3 1.5 1.0 1.0)) 时，正面那块高光从 0.41 掉到 0.15；把 1.5 换成 4.0，高光干脆消失（0.47 → 0.00）。试试看第 ④ 条就是干这个的。

9.3 在片元里算 + 布局用 shader-struct

三项都在片元着色器里算，不在顶点着色器里算。原因是法线从顶点传到片元时会被插值：立方体每个面的 4 个顶点法线相同，插值完整个面还是同一个法线，于是得到一个平整的面；换成曲面（球、地形）时相邻顶点的法线不同，插值后每个像素拿到一条略微不同的法线，高光才会顺着表面平滑铺开。要是改在顶点里算好颜色再插值，高光会被「摊」在三角形顶点之间，看到的是面与面之间的硬边，而不是一整片高光。所以顶点着色器本课只管两件事：把位置算进 gl-position、把法线和世界坐标传给片元。

片元里就是 9.1 那三个公式，一个不多。它和 9.1.5 的 CPU 脚本 phong 逐行对应，区别只在这里对每个像素跑一次：

命名racket-shader 会把 shader 表面名字里的连字符换成 GLSL 的 _：light-dir 生成 light_dir，v-normal 生成 v_normal，u-light-pos 生成 u_light_pos。所以 shader 和 Racket 侧都可以统一用 kebab-case。

09-basic-lighting/basic-lighting.rkt：片元里逐像素算三项源码 ↗
        (define (main) void
          (vec-3 norm (normalize v-normal))
          (vec-3 light-dir (normalize (- u-light-pos v-frag-pos)))
          (float ambient 0.1)
          (float diff (max (dot norm light-dir) 0.0))
          (vec-3 reflect-dir (reflect (- light-dir) norm))
          (vec-3 view-dir (normalize (- u-view-pos v-frag-pos)))
          (float spec (* (pow (max (dot view-dir reflect-dir) 0.0) 32.0) 0.5))
          (set! frag-color (vec-4 (* (+ ambient diff spec) u-light-color u-object-color) 1.0)))))

再看顶点怎么摆。一个顶点现在要带 6 个数：位置 3 个 + 法线 3 个。03/04 课已经消掉了字节字面量（shader-stride-bytes / shader-byte-size 按类型名算步长与偏移）；本课再往前一步，让 CPU 侧直接镜像 shader 的顶点结构——shader-struct 声明一张字段表，步长和每个字段的偏移就都跟着字段名走：

09-basic-lighting/basic-lighting.rkt：把顶点结构镜像到 CPU 侧源码 ↗
(shader-struct vertex (vec-3 pos) (vec-3 normal))

shader-struct 除生成一个 Racket struct，还生成一组按布局查询的函数：

函数查什么返回
vertex-fields字段表（编译期）：字段名 + 类型((pos vec3) (normal vec3))
vertex-stride-bytes一条记录占多少字节24
vertex-field-offset某个字段在记录里的字节偏移pos → 0，normal → 12
vertex-field-components某个字段有几个分量pos → 3
vertex->f32vector把一个记录铺平成连续字节（打包用）f32vector

前缀就是 struct 名：换一个名字（14 课的 model-vertex）就是 model-vertex-stride-bytes 这一套。

于是 24 个顶点就是 24 个 vertex 记录：每个记录既是一对「位置 + 法线」的值，也能铺平成一条连续的 float 缓冲喂给 VBO。绑定属性时不再数字节，直接问字段名：

09-basic-lighting/basic-lighting.rkt：铺平缓冲 + 用字段名绑定属性源码 ↗
(define cube-data (apply concat-vecs (map vertex->f32vector cube-verts)))
09-basic-lighting/basic-lighting.rkt：描述 pos 与 normal 两个属性源码 ↗
  ;; 参数依次是 location / 分量数 / 类型 / normalized / 步长 / 偏移
  (gl-vertex-attrib-pointer 0 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'pos))
  (gl-enable-vertex-attrib-array 0)
  (gl-vertex-attrib-pointer 1 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'normal))
  (gl-enable-vertex-attrib-array 1)

图 9-3 是这条缓冲在内存里的样子：每 6 个 float（24 字节）是一个顶点，前 3 个是位置、后 3 个是法线。GPU 每 24 字节取下一个顶点；读法线时从每个顶点的第 12 字节开始，读 3 个 float。这两个数不用手写——(vertex-stride-bytes) 和 (vertex-field-offset 'normal) 从字段表算出来。

9.4 属性布局与 uniform 位置

顶点属性用 gl-vertex-attrib-pointer 描述：一个属性槽一次调用，槽默认关闭，再用 gl-enable-vertex-attrib-array 打开。

属性 0（pos）与属性 1（normal）
(gl-vertex-attrib-pointer 0 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'pos))
(gl-enable-vertex-attrib-array 0)
(gl-vertex-attrib-pointer 1 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'normal))
(gl-enable-vertex-attrib-array 1)

六个参数依次是：

参数本例含义 / 为什么是这个值
location0 / 1属性槽编号，必须等于 shader 里 layout(location N) 的 N；对不上就读错数据
size3属性有几个分量：vec3 是 3，vec2 是 2
typegl-float每个分量的类型；数据是 float 就用 gl-float
normalized#f浮点数据不需要归一化；整数数据要映射到 0..1 时才传 #t
stride24从一个顶点走到下一个要跨多少字节：6 个 float × 4
offset0 / 12属性在顶点内部从第几个字节开始：pos 在 0，normal 在 3 个 float 之后

gl-enable-vertex-attrib-array 不能省：属性槽初始是关闭的，关闭时着色器读到常量 (0,0,0,1)，画面坏掉但不报错。

最后两个参数来自 shader-struct 的字段表：vertex-stride-bytes 是整条记录的字节数，vertex-field-offset 按字段名给出偏移。打包和属性描述读同一份布局，加字段时两边一起变。

uniform 没有「槽」可写，只能在 program 链接后按名字查位置：

uniform 位置：链接后查一次，draw 里直接用
;; init 里，build-program 之后
(set! obj-u-model-loc (uniform-location object-program "u_model"))

;; draw 里
(uniform-set! obj-u-model-loc 'mat-4 model)
  • uniform-location 的第二个参数是 GLSL 里的名字（u_model），不是 Racket 侧的连字符名；找不到时返回 -1。
  • 位置只查一次：链接后布局就固定了，每帧再查只是白跑驱动。
  • uniform-set! 的类型符号（'mat-4 / 'vec-3 / 'sampler-2d）决定调用哪个 gl-uniform-*，要和 shader 里的声明一致。

#lang glsl-opengl
;; ============================================================
;; 09 · 基础光照：ambient + diffuse + specular
;; 运行：racket 09-basic-lighting/basic-lighting.rkt
;; 上一课：08-colors/colors.rkt
;; ============================================================
;; 目标：08 课只会"物体色 × 光色"，颜色有了，但整块立方体每一面一样亮——那一步里
;; 没有"方向"：光从哪来、面朝哪，都不影响结果。本课把方向补上，逐片元算 Phong 三项：
;;   ambient   保底光：面完全背光时也有点亮度，否则背光面纯黑、不像真实世界
;;   diffuse   漫反射：面越正对光源越亮，背向为 0（max(dot(n,l), 0)）
;;   specular  镜面高光：反射方向恰好对着眼睛时才亮（pow(max(dot(v,r),0), 32)）
;; 要算这三项，片元得知道两件它现在不知道的事：这一点的法线、这一点在世界里的位置。
;; 于是顶点着色器第一次多传两个量出去（v-normal / v-frag-pos），法线属性（location 1）
;; 和"法线矩阵"也在本课第一次登场。
;;
;; 顶点布局本课也换了写法：用 shader-struct 把 shader 的 struct 镜像到 CPU 侧，
;; 步长和偏移全部由字段名给出——03/04 课的 shader-stride-bytes / shader-byte-size
;; 又往前走了一步。

(require racket/class
         racket/math                     ; degrees->radians
         "../lib/window.rkt"
         "../lib/matrix.rkt")            ; m-look-at / m-perspective / m-normal-matrix / …

;; ------------------------------------------------------------
;; 一、窗口尺寸与 aspect（同 06 / 08 课）
;; ------------------------------------------------------------
;; 投影要一个 aspect = 宽/高，必须和窗口客户区同源，否则画面会被拉伸。
(define win-w 800)
(define win-h 600)
(define aspect (/ win-w win-h))

;; ------------------------------------------------------------
;; 二、着色器
;; ------------------------------------------------------------
;; 顶点着色器除了把位置算好，还要多带两个插值量给片元：
;;   v-frag-pos  这个顶点在世界里的位置（片元里插值后 ≈ 每个像素的世界位置）
;;   v-normal   世界空间的法线（片元里插值后 ≈ 每个像素的法线）
;; 光照明亮程度必须逐片元算，这两个量就是它要的输入。
;;
;; (glsl-shader name form ...) 与 (glsl ...) 一样产出 shader，并额外把编译期接口表
;; 绑为 name-interface：展开成一张编译期表（每个变量的名字、类型、qualifier、layout），
;; 供想在展开期读接口的代码使用。裸等价： (define name (glsl ...))，接口只能运行期取。
(glsl-shader vert-src
  (version 330 core)
  (layout (location 0) in vec-3 pos)       ; 属性名 = CPU 侧 shader-struct 字段名
  (layout (location 1) in vec-3 normal)
  (uniform mat-4 u-model)                   ; 局部 → 世界
  (uniform mat-4 u-view)                    ; 世界 → 观察
  (uniform mat-4 u-proj)                    ; 观察 → 裁剪
  (uniform mat-3 u-normal-matrix)            ; 法线专用的 mat-3，为什么不是 u-model 见 9.2
  (out vec-3 v-normal)
  (out vec-3 v-frag-pos)
  (define (main) void
    (set! v-normal (* u-normal-matrix normal))
    (set! v-frag-pos (vec-3 (* u-model (vec-4 pos 1.0))))
    (set! gl-position (* u-proj (* u-view (* u-model (vec-4 pos 1.0)))))))

;; 物体的片元：本课的全部内容。三项相加，最后乘光色和物色——08 课那一步还在，
;; 只是现在"光有多少"不再是个常数，而是逐像素算出来的 ambient + diff + spec。
;;
;; light-dir（l）从片元指向光源；view-dir（v）从片元指向相机；reflect-dir（r）
;; 是 l 打到表面上弹开的方向，也就是"光被镜面反射到哪去了"。
;; 眼睛正好站在 r 上（v 与 r 重合）时就看见高光。
;; （这里用 Racket 风格的连字符；racket-shader 会换成 GLSL 的 _，生成文本里是 light_dir / v_normal。）
(glsl-shader frag-src
  (version 330 core)
  (in vec-3 v-normal)
  (in vec-3 v-frag-pos)
  (uniform vec-3 u-light-pos)               ; 光源位置（世界坐标）
  (uniform vec-3 u-light-color)             ; 光的颜色（同 08 课）
  (uniform vec-3 u-view-pos)                ; 相机位置（世界坐标）——高光要它
  (uniform vec-3 u-object-color)            ; 物体本色（同 08 课）
  (out vec-4 frag-color)
  (define (main) void
    (vec-3 norm (normalize v-normal))
    (vec-3 light-dir (normalize (- u-light-pos v-frag-pos)))
    (float ambient 0.1)
    (float diff (max (dot norm light-dir) 0.0))
    (vec-3 reflect-dir (reflect (- light-dir) norm))
    (vec-3 view-dir (normalize (- u-view-pos v-frag-pos)))
    (float spec (* (pow (max (dot view-dir reflect-dir) 0.0) 32.0) 0.5))
    (set! frag-color (vec-4 (* (+ ambient diff spec) u-light-color u-object-color) 1.0))))

;; 灯自己的两个 shader（同 08 课思路）：顶点只要位置，片元只把光色原样输出。
;; 灯是光本身，不是"被光照到的东西"，所以它不算法线、不做那三项。
;; 注意它只声明 location 0——下面那个 VAO 多开的 normal 槽（location 1）在没有
;; 对应 in 的 program 里会被 GL 忽略，灯照画不误（08 课末尾预告过这件事）。
(glsl-shader lamp-vert-src
  (version 330 core)
  (layout (location 0) in vec-3 pos)
  (uniform mat-4 u-model)
  (uniform mat-4 u-view)
  (uniform mat-4 u-proj)
  (define (main) void
    (set! gl-position (* u-proj (* u-view (* u-model (vec-4 pos 1.0)))))))

(glsl-shader lamp-frag-src
  (version 330 core)
  (uniform vec-3 u-light-color)
  (out vec-4 frag-color)
  (define (main) void
    (set! frag-color (vec-4 u-light-color 1.0))))

;; ------------------------------------------------------------
;; 三、立方体几何：24 个顶点，每个带位置 + 法线
;; ------------------------------------------------------------
;; 和 06 / 08 课是同一个立方体、同样的 24 顶点 / 36 索引（06 课解释过为什么不是 8 个：
;; 每个面得摊自己的一份顶点）。本课一个顶点多带一条法线：法线是"这个面朝哪边"，
;; 三项光照全靠它。同一个空间角落在不同的面上法线不同（前面 (0,0,1)、右面 (1,0,0)…），
;; 所以还是 24 个顶点、每个面 4 个。
;;
;; shader-struct 把 shader 的 struct 镜像到 CPU 侧：字段名、类型、顺序和 shader 里一致。
;; 它顺带给出 stride / 字段偏移（vertex-stride-bytes / vertex-field-offset），
;; 打包和属性描述都用这两个函数，所以不用数字节；location、分量数、GL 类型
;; 要自己写（见下面 init 里的 gl-vertex-attrib-pointer）。
(shader-struct vertex (vec-3 pos) (vec-3 normal))

;; 四、场景：一个物体 + 一盏灯 + 一台不动的相机

(define object-color (vec-3 1.0 0.5 0.31))      ; 物体本色：橙（同 08 课）
(define light-color (vec-3 1.0 1.0 1.0))        ; 光的颜色：白
(define light-pos (vec-3 1.2 1.0 2.0))          ; 光在世界里的位置：物体右上前方
(define eye-pos (vec-3 0.0 0.0 3.0))            ; 相机位置：本课不动

;; model 是个固定的倾斜姿态：先绕 x 轴 -12°，再绕 y 轴 15°（从右往左作用）。
;; 为什么不干脆摆成单位矩阵：相机和立方体中心一样高，轴对齐时会看到前 / 上 / 右
;; 三个面，而这三个面恰好都朝着光——"背光面只剩环境光"就看不见了。稍微转一下：
;;   正面    法线 ≈ (0.25, 0.21, 0.95)，正好落在"光与眼睛的中间方向"上 → 中央一块高光
;;   左面    法线转成 (-0.97, 0, 0.26)，背对光 → 只剩 ambient，但还朝着镜头
;;   底面    也翻到朝着镜头的一侧、同样背对光 → 也只剩 ambient
;; 于是 ambient / diffuse / specular 三项在同一帧里都看得见。
(define model
  (mat4-mul (m-rotate-y (degrees->radians 15.0))
            (m-rotate-x (degrees->radians -12.0))))

(define object-program 0)
(define lamp-program 0)
;; uniform 位置：链接后查一次（名字用 GLSL 里的写法），之后每帧直接 uniform-set!
(define obj-u-model-loc 0)
(define obj-u-view-loc 0)
(define obj-u-proj-loc 0)
(define obj-u-normal-matrix-loc 0)
(define obj-u-light-pos-loc 0)
(define obj-u-light-color-loc 0)
(define obj-u-view-pos-loc 0)
(define obj-u-object-color-loc 0)
(define lamp-u-model-loc 0)
(define lamp-u-view-loc 0)
(define lamp-u-proj-loc 0)
(define lamp-u-light-color-loc 0)
(define vao 0)

;; uniform 位置：每个 uniform 在链接后查一次，存进变量，draw 里直接用 uniform-set!。
;; 名字用 GLSL 里的写法（u_model），类型用 GLSL 的类型符号（mat-4）。
;; 两个 program 的 uniform 同名，所以各带前缀区分（obj- / lamp-）。

;; 这些缓冲句柄也放在顶层：关窗时 shutdown 要能拿到（0 = 还没创建）
(define vbo 0)
(define ebo 0)

(define (init)
  (set! object-program (build-program (gl-vertex-shader vert-src)
                                      (gl-fragment-shader frag-src)))
  (set! obj-u-model-loc (uniform-location object-program "u_model"))
  (set! obj-u-view-loc (uniform-location object-program "u_view"))
  (set! obj-u-proj-loc (uniform-location object-program "u_proj"))
  (set! obj-u-normal-matrix-loc (uniform-location object-program "u_normal_matrix"))
  (set! obj-u-light-pos-loc (uniform-location object-program "u_light_pos"))
  (set! obj-u-light-color-loc (uniform-location object-program "u_light_color"))
  (set! obj-u-view-pos-loc (uniform-location object-program "u_view_pos"))
  (set! obj-u-object-color-loc (uniform-location object-program "u_object_color"))
  (set! lamp-program (build-program (gl-vertex-shader lamp-vert-src)
                                    (gl-fragment-shader lamp-frag-src)))
  (set! lamp-u-model-loc (uniform-location lamp-program "u_model"))
  (set! lamp-u-view-loc (uniform-location lamp-program "u_view"))
  (set! lamp-u-proj-loc (uniform-location lamp-program "u_proj"))
  (set! lamp-u-light-color-loc (uniform-location lamp-program "u_light_color"))

  ;; 画立体的东西就得开深度测试（06 课）。
  (gl-enable gl-depth-test)

  ;; ---- VAO / VBO / EBO ----
  (set! vao (vertex-array-new))
  (gl-bind-vertex-array vao)

  (set! vbo (buffer-new))
  (gl-bind-buffer gl-array-buffer vbo)
  (buffer-upload gl-array-buffer cube-data gl-static-draw)
  ;; 属性布局：location 必须和 shader 的 layout(location N) 对上（0 = pos，1 = normal）。
  ;; 分量数/类型跟着字段类型写；步长和偏移来自 shader-struct 的字段表，不用数字节
  ;; （pos 在 0，normal 在 12，步长 24 = 6 个 float）。
  (gl-vertex-attrib-pointer 0 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'pos))
  (gl-enable-vertex-attrib-array 0)
  (gl-vertex-attrib-pointer 1 3 gl-float #f (vertex-stride-bytes) (vertex-field-offset 'normal))
  (gl-enable-vertex-attrib-array 1)

  (set! ebo (buffer-new))
  (gl-bind-buffer gl-element-array-buffer ebo)
  (buffer-upload gl-element-array-buffer indices gl-static-draw)

  (gl-bind-vertex-array 0))

(define (draw)
  (gl-clear-color 0.10 0.12 0.20 1.0)
  ;; 颜色和深度一起擦（掩码，01 课）。
  (gl-clear (bitwise-ior gl-color-buffer-bit gl-depth-buffer-bit))

  ;; 相机固定 (0,0,3) 看向原点（同 08 课）。u-view-pos 就是它的位置——片元算高光要用。
  (define view (m-look-at eye-pos (vec-3 0.0 0.0 0.0) (vec-3 0.0 1.0 0.0)))
  (define proj (m-perspective (degrees->radians 45.0) aspect 0.1 100.0))

  (gl-bind-vertex-array vao)

  ;; ---- 物体：逐片元算 ambient + diffuse + specular ----
  (program-use object-program)
  ;; 位置已经在上面的 init 里查过一次；这里直接 uniform-set!（类型跟 shader 声明一致）。
  (uniform-set! obj-u-model-loc 'mat-4 model)
  (uniform-set! obj-u-view-loc 'mat-4 view)
  (uniform-set! obj-u-proj-loc 'mat-4 proj)
  ;; 法线矩阵是 mat-3，uniform-set! 按类型符号选 matrix-3fv，transpose 固定 #f：
  ;; lib/matrix.rkt 的矩阵都是列主序，正好是 GL 要的，传 #t 会让它转错。
  (uniform-set! obj-u-normal-matrix-loc 'mat-3 (m-normal-matrix model))
  (uniform-set! obj-u-light-pos-loc 'vec-3 light-pos)
  (uniform-set! obj-u-light-color-loc 'vec-3 light-color)
  (uniform-set! obj-u-view-pos-loc 'vec-3 eye-pos)
  (uniform-set! obj-u-object-color-loc 'vec-3 object-color)
  (gl-draw-elements gl-triangles 36 gl-unsigned-short 0)

  ;; ---- 灯：同一份 VAO、换个 program，片元只输出光色（同 08 课） ----
  (program-use lamp-program)
  ;; 灯比物体小：先缩到 0.2 倍，再搬到 light-pos（从右往左作用在顶点上）。
  (uniform-set! lamp-u-model-loc 'mat-4 (mat4-mul (m-translate light-pos) (m-scale (vec-3 0.2 0.2 0.2))))
  (uniform-set! lamp-u-view-loc 'mat-4 view)
  (uniform-set! lamp-u-proj-loc 'mat-4 proj)
  (uniform-set! lamp-u-light-color-loc 'vec-3 light-color)
  (gl-draw-elements gl-triangles 36 gl-unsigned-short 0)

  (gl-bind-vertex-array 0))

;; ------------------------------------------------------------
;; 关窗前释放：这些句柄归调用方，不删就一直占着显存
;; ------------------------------------------------------------
;; 顺序：先解绑当前状态，再删引用方（VAO）→ 缓冲 → 纹理 → program。
;; 初始值是 0：0 不是有效对象，GL 的 delete 会忽略它（init 没跑完也能安全关窗）。
(define (shutdown)
  (gl-bind-vertex-array 0)      ; 别删正在用的
  (gl-use-program 0)
  (vertex-array-delete vao)
  (buffer-delete vbo)
  (buffer-delete ebo)
  (program-delete object-program)
  (program-delete lamp-program))

(define-values (frame canvas)
  (make-window #:title "09 基础光照"
               #:width win-w
               #:height win-h
               #:init init
               #:draw draw
               ;; 窗口尺寸变化、viewport 重设之后被调用，参数是新的客户区宽高。
               #:on-size (lambda (cw ch) (set! aspect (/ cw ch)))
               #:on-close shutdown))
(send frame show #t)

试试看

  1. 把 ambient 从 0.1 改成 0.5：背光那两面（左面和底面）立刻被抬亮，整块立方体的明暗对比变平——这就是「环境光是保底亮度」的直观样子。
  2. 把 spec 里的指数 32.0 改成 4.0：高光不再是一个小圆点，而是糊成一大片。指数越小越像磨砂，越大越像镜子。
  3. 把 light-pos 改成 (vec-3 0.0 3.0 0.0)（正上方）：能看见的三个面没有一个正对光，diff 几乎全变成 0，整块立方体暗下来只剩 ambient——「正上方最该亮的顶面」这时恰好背向镜头（相机和立方体中心一样高，顶面只能看到一条边），别指望看到它变亮。再把 light-pos 换成 (vec-3 -2.0 -0.5 2.0)（左下前方）就反过来了：现在亮的那面变暗、现在暗的左面和底面变亮，高光也跟着挪到它们上面。
  4. 给 model 加一个非等比缩放：(define scaled (mat4-mul (m-scale (vec-3 1.5 1.0 1.0)) model))，先照原样上传 (m-normal-matrix scaled)——法线仍然垂直于表面、画面正常。再把上传换成 naive 版本（只取左上 3×3、去掉逆转置；现成的写法在本课源码文件末尾的注释里），正面的高光立刻暗下去：法线被 x 方向拉走约 11.5°，dot(v, r) 跟着偏，高光那一项从 0.41 只剩 0.15；把 1.5 换成 4.0，法线偏了 42.6°、高光彻底消失——「光照错在哪」看得一清二楚。改完记得换回来。
  5. 把 light-pos（以及灯立方体的位置）的 z 从 2.0 改成 0.0——也就是 08 课的机位：灯会走进画面右上角，同时高光从正面中央挪开。对照两课就能看清「光的位置」同时管着两件事：灯立方体画在哪、以及三项光照各自往哪个方向算。

GPU 资源本节创建的 program / VAO / VBO（以及纹理）都在文件末尾的 shutdown 里用 program-delete / vertex-array-delete / buffer-delete 显式删除，由 #:on-close shutdown 在关窗时触发。为什么这些句柄 GC 管不了、为什么必须手动删，见 02 · 2.9。

小结

概念 一句话
ambient / diffuse / specular 保底光；max(dot(n,l),0) 管面朝向；pow(max(dot(v,r),0),32) 管镜面反射；三项相加再乘光色与物色
逐片元 vs 逐顶点 在片元里算插值后的法线，曲面才有平滑高光；在顶点里算完再插值颜色，会看到面与面之间的硬边
法线属性 顶点第一次多带一条 vec-3 法线（location 1），片元拿它算三项
normal matrix transpose(inverse(mat-3(model)))；非等比缩放时直接拿 model 转法线会把它带歪（本课这套参数下差 11.5°）
mat-3 上传 (uniform-set! obj-u-normal-matrix-loc 'mat-3 (m-normal-matrix model)) 内部选 gl-uniform-matrix-3fv 且 transpose 固定 #f——列主序与 lib/matrix.rkt 一致
shader-struct 把 shader 的顶点结构镜像到 CPU 侧：给出字段表、步长与字段偏移（vertex-stride-bytes / vertex-field-offset），打包和 attrib 调用都用它；location / 分量数要自己写
